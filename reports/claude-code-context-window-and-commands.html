Claude Codeのコンテキストとコンテキストウィンドウ：仕組みと管理コマンド

  • 作成日 2026-10-03
  • 分野 AI
  • 確認日 2026-10-03（公式ドキュメント。コマンドや閾値はバージョンで変わる）

概要

3行でいうと
  1. コンテキストとは、Claudeが1回の応答のたびに読み返す「作業机の上の全部」で、その広さの上限がコンテキストウィンドウ。会話だけでなく、CLAUDE.md・ツール定義・読んだファイルも載る。
  2. ウィンドウが埋まりそうになると、古い会話を要約に置き換える自動圧縮（auto-compact）が働く。手動なら /compact、全部捨てて始めるなら /clear、中身を見るなら /context。
  3. 節約の基本は、「無関係な作業の間に /clear」「長い出力はサブエージェントに任せる」「CLAUDE.mdは短く」。コンテキストが小さいほど、速く・安く・指示が守られやすい。

Claude Codeを長く使っていると、「だんだん動きが鈍い」「さっき決めたことを忘れた」「使用量の減りが速い」と感じることがあります。原因の多くはコンテキストです。このノートでは、コンテキストに何が入り、いっぱいになると何が起き、どのコマンドで管理するかを、公式ドキュメントに沿って整理します。

CLAUDE.md・Skill・Hooks・サブエージェントなど各拡張の違いは、別のノートClaude Codeの拡張の全体像：どの仕組みをいつ使うかが詳しく扱っています。このノートは「それぞれがコンテキストをどう使うか」という視点に絞ります。

基本用語

用語意味
コンテキストClaudeが応答を作るときに参照する情報の全体。システムプロンプト、CLAUDE.md、自動メモリ、ツール定義、あなたの発言、Claudeの返答、読んだファイル、コマンド出力などを含む。
コンテキストウィンドウ一度に扱える情報量の上限。単位はトークン。モデルによって200Kや1M（100万）トークンなど違う。
トークン文字より細かいテキストの単位。長さの目安であり、料金・使用量の計算単位でもある。
自動圧縮（auto-compact）ウィンドウが閉じる前に、会話を構造化された要約へ置き換えて空きを作る仕組み。
セッション1つの会話のまとまり。新しいセッションは空のコンテキストから始まる。CLAUDE.mdなどは毎回読み直される。
CLAUDE.mdあなたが書く、プロジェクト共通の指示ファイル。毎セッションの開始時にコンテキストへ読み込まれる。
自動メモリ（auto memory）Claude自身が過去の訂正や好みから書き溜めるメモ。MEMORY.mdの先頭200行か25KBまでが読み込まれる。
サブエージェント独立したコンテキストウィンドウで作業し、最終的な要約だけを本会話へ返す補助エージェント。
プロンプトキャッシュ繰り返し送る同じ部分（システムプロンプトなど）を安く再利用する仕組み。放置するとキャッシュが切れて、再処理になる。

仕組み・全体像

コンテキストに入るもの

Claude Codeは、リクエストのたびに会話全体をまとめて送ります。あなたが最初のメッセージを打つ前から、すでに多くのものが読み込まれています。公式の「コンテキストウィンドウを探る」ページのシミュレーションでは、起動時に次のものが自動で載ります。

載るものいつ載るか補足
システムプロンプト起動時振る舞い・ツールの使い方の基本指示。ユーザーには見えない。
CLAUDE.md起動時階層（ユーザー・プロジェクトなど）ごとに読み込まれる。
自動メモリ起動時先頭200行または25KBまで。
環境情報・Gitの状態起動時作業ディレクトリ、OS、ブランチなど。
MCPツール起動時（名前のみ）既定では詳細スキーマは遅延読み込み。必要になった時にツール検索で取り込む。
スキルの一覧起動時説明文だけ載り、本体は呼ばれた時に載る。
あなたの発言・Claudeの返答やり取りのたび会話が続くほど積み上がる。
読んだファイル・コマンド出力ツール実行のたび実は一番かさばりやすい。
サブエージェントの返答完了時最終要約のみ。中の作業は載らない。

ポイントは、あなたの発言が全体のごく一部にすぎないことです。公式のシミュレーションでも、コンテキストの大半を占めるのはプロジェクトの知識とファイルの中身でした。

重いのは発言より、読んだファイル

埋まるとどうなるか

やさしく図解

会話が長くなるとウィンドウに余裕がなくなります。このときClaude Codeは、古い会話を要約へ置き換えて空きを作ります。これが自動圧縮です。いつ発動するかはモデルによって違い、公式ドキュメントでは次のように説明されています（確認日時点）。

モデル・条件自動圧縮のタイミング（既定）
Sonnet 4.6 / Opus 4.6（拡張コンテキストなし）200Kトークン付近
Opus 4.8以降（200Kウィンドウの場合）200Kトークン付近
1Mがネイティブのモデル（Sonnet 5、Fable系、Opus 4.7以降など）約967Kトークン付近
CLAUDE_CODE_DISABLE_1M_CONTEXT=1 を設定1Mモデルでも200K付近

この閾値は /autocompact コマンド（100Kから1Mトークンの範囲で指定可能）、--autocompact フラグ、設定ファイルの autoCompactWindow、環境変数 CLAUDE_CODE_AUTO_COMPACT_WINDOW で変えられます。環境変数が一番優先されます。

設定が効かないときは環境変数を疑う

圧縮後に残るもの

圧縮は「全部を記憶したまま小さくする」ものではありません。元の会話は、要望・重要な技術的概念・触ったファイルと主要なコード片・エラーとその直し方・残タスク・今の作業、を中心にした要約に置き換わります。ツールの出力全文や途中の思考は失われます。公式のシミュレーションで説明されている、圧縮後の扱いは次のとおりです。

項目圧縮後
システムプロンプト、CLAUDE.md、自動メモリ、MCPツール自動的に読み込み直される
会話そのもの構造化された要約に置き換わる（逐語は消える）
直近に触ったファイル最近変更した最大5つほどを再読み込みする
呼び出し済みのスキル本文を再投入する。1スキルあたり先頭5,000トークンまで、合計25,000トークンの予算
スキルの一覧再読み込みされない

つまり、会話の中だけで伝えた指示は要約で薄まるが、CLAUDE.mdに書いた指示は毎回読み直される、という違いが生まれます。長く守らせたいルールはCLAUDE.mdへ、という指針はここから来ています。

覚え方：会話は薄まる、CLAUDE.mdは残る

サブエージェントの別枠

やさしく図解

サブエージェントは、新しい白紙のコンテキストウィンドウで始まります。あなたの会話履歴や、すでに読んだファイルは引き継がれません。代わりにそれ自身のシステムプロンプト、委任のメッセージ、CLAUDE.md、Gitの状態などを持ちます。作業中に読んだ大量のファイルやログはサブエージェント側に溜まり、本会話に戻るのは最終的な要約だけです。公式のシミュレーションでは、6,100トークン分のファイルを読んだ結果、本会話に戻ったのは約420トークンでした。

履歴は渡らないので、頼む文に要点を

本会話が圧縮されても、サブエージェントの記録には影響しません。また、サブエージェント自身も同じ条件で自動圧縮されます。サブエージェント、CLAUDE.md、Hooksなどの比較は拡張の全体像のノートを参照してください。

具体例・使いどころ

コンテキスト管理コマンド

公式のコマンド一覧（Commands）で存在を確認できたものだけを載せます。

迷ったら、まず /context
コマンド何をするか使いどころ
/context [all]今のコンテキスト使用量を色付きのグリッドで表示。重いツールやメモリの肥大化、容量の警告も出る。all で内訳を展開。「何が場所を取っているか」を調べる最初の一手。
/compact [instructions]会話を要約して空きを作る。指示を付けると要約で重視する点を指定できる。同じ作業を続けたいが、会話が長くなってきたとき。
/clear [name]空のコンテキストで新しい会話を始める。名前を付けると /resume の一覧で見つけやすい。別名 /reset、/new。無関係な作業に切り替えるとき。
/usageセッションのトークン使用量と費用の目安、プランの使用状況を表示。/cost は /usage の別名（エイリアス）。使用量・費用の確認。
/autocompact [auto|トークン数]自動圧縮が発動するウィンドウの大きさを設定する。v2.1.221以降。早めに圧縮したいとき。
/memoryCLAUDE.mdの編集、自動メモリのオン／オフと内容の確認。毎回読み込まれる指示の見直し。
/resume [session]以前の会話を名前かIDで再開する。別名 /continue。/clear のあとで元の会話へ戻るとき。
/rewind会話やコードを以前の時点に戻す、または選んだメッセージ以降を要約する。別名 /checkpoint、/undo。脱線した方向を戻すとき。
/btw [question]会話履歴に追加せずに、ちょっとした横道の質問をする。本筋を汚したくない質問。
/rename [name]セッションに名前を付ける。/clear の前に付けておくと再開しやすい。
/mcpMCPサーバーの接続を管理。使わないサーバーは無効にできる。ツール定義による消費の削減。
/doctor使っていないスキル・MCP・プラグインと、そのコンテキスト消費を洗い出し、肥大したCLAUDE.mdの整理も提案する。設定全体の棚卸し。

なお、/agents は現在（v2.1.198以降）、対話画面を開かず「サブエージェントの作成や管理はClaudeに頼む、または .claude/agents/ を直接編集する」という案内を表示します。古い解説と動きが違う点に注意してください。

カスタム圧縮の指示

圧縮の方針は、コマンドの引数かCLAUDE.mdで指定できます。

# その場で指定する
/compact Focus on code samples and API usage

# CLAUDE.md に書いておく
# Compact instructions
When you are using compact, please focus on test output and code changes

節約の実践テクニック

やること節約になる理由
無関係な作業に移る前に /clear古い文脈は、以降のすべてのメッセージで毎回送られ続ける。
ログ・テスト・調査はサブエージェントへ大量の出力が本会話に入らず、要約だけが戻る。
CLAUDE.mdは200行以内の要点だけにする毎セッション常に載る。作業別の詳しい手順はスキルへ移すと、必要な時にだけ載る。
具体的に頼む（「auth.tsのログイン関数に入力検証を足して」）「コードを改善して」のような曖昧な依頼は、広範囲を読み込みに行ってしまう。
使わないMCPサーバーを無効にする、可能なら gh などCLIを使うCLIはツール一覧を増やさない。
複雑な作業はShift+Tabのプランモードで先に方針を決めるやり直しによる無駄な読み書きを防ぐ。
方向違いに気づいたらEscで止め、/rewind で戻す間違った方向の履歴を積み上げない。
簡単な作業はSonnet、サブエージェントは model: haiku も検討単価が下がる（コンテキストの大きさとは別の軸）。
ステータスラインにコンテキスト使用量を表示する常に残量が目に入る。

注意点・よくある誤解

よくある誤解1：「/clearすると全部忘れて、CLAUDE.mdも消える」

消えるのは会話です。新しいセッションでもCLAUDE.mdや自動メモリは読み直されます。/clear は「会話の白紙化」で、プロジェクトの記憶は保たれます。公式の説明でも、/clear は「プロジェクトの記憶を残したまま新しい作業を始める」ためのコマンドです。

よくある誤解2：「/compactは無料で、やるほど得」

/compact は要約のために会話を読むので、大きなコンテキストの圧縮はそれ自体が大きなリクエストになります。さらに、圧縮するとキャッシュが作り直しになり、細かい逐語の情報も失われます。続きが不要なら、費用がかからない /clear のほうが適しています。

よくある誤解3：「/costは廃止された、または /usageと別物」

現在の公式ドキュメントでは、/cost は /usage の別名と書かれています。表示される金額はAPI料金換算の見積りで、PlanのPro／Maxではサブスクリプションに含まれるため請求額ではありません（正式な請求はConsoleで確認）。

よくある誤解4：「ウィンドウが大きければ、何を載せても大丈夫」

大きなウィンドウは上限が伸びるだけです。リクエストのたびに会話全体が送られるため、長いセッションは1回ごとに使用量が増えます。公式も、一日中開いたセッションでは短い質問でも会話全体分の使用量がかかる、と説明しています。

補足

プロンプトキャッシュには有効期間があり、休憩が長いと最初のメッセージでキャッシュが外れ、全コンテキストの再処理になります。サブスクリプションでは1時間、APIキーの既定では5分です。大きなセッションに長い休みの後で戻るなら、要約から再開する選択肢が提示される場合があります。

補足

CLAUDE.mdは強制ではなくコンテキストとして扱われます。「絶対に実行させない」ことはHooks（PreToolUse）で止めるのが確実です。詳しくは拡張の全体像のノートへ。

確認問題

Q1. コンテキストウィンドウに入るものを、会話以外で3つ挙げてください。

例：システムプロンプト、CLAUDE.md、自動メモリ、MCPツール名、スキルの一覧、環境情報、読んだファイルの中身、コマンドの出力。いずれも3つ挙がれば正解です。

Q2. 別の機能の作業に移りたい。会話の続きは要らない。/compact と /clear のどちらが適切で、なぜですか。

/clear です。続きが不要なら古い文脈は無駄であり、/clear は費用がかからず、CLAUDE.mdは新しい会話でも読み込まれます。/compact は同じ作業を続けたい場合に使います。

Q3. 自動圧縮のあとでも確実に残ってほしいルールは、どこに書くべきですか。

CLAUDE.mdです。圧縮後も読み込み直されます。会話の中だけで伝えたルールは、要約で薄まる可能性があります。

Q4. 大量のテストログを調べさせたい。本会話のコンテキストを汚さないための方法は何ですか。

サブエージェントに任せます。サブエージェントは独立したコンテキストで作業し、最終的な要約だけが本会話に戻ります。

Q5. 今、何がコンテキストを占めているのか調べたい。どのコマンドを使いますか。

/context です。使用量をグリッドで表示し、重いツールやメモリ肥大の提案も出ます。all を付けると内訳を展開できます。費用は /usage（別名 /cost）で見ます。
