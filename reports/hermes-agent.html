Hermes Agentとは何か：使うほど育つ自己ホスト型AIエージェント

  • 作成日 2026-10-06
  • 分野 AI

概要

3行でいうと
  1. Hermes Agentは、AIモデル「Hermes」を作っているNous Researchが2026年2月に公開した、MITライセンスのオープンソースAIエージェントで、自分のPCやサーバーで動かす。
  2. 最大の特徴は「学習ループ」。作業の中で手順を「スキル」として書き溜め、会話をまたいで記憶し、次回以降の仕事に使い回す。
  3. 本体は無料で、Telegram・Discord・Slackなどからも話しかけられる。一方で、モデルのAPI料金、設定の手間、自分で書いたスキルや記憶が誤ったり汚染されたりする危険は、自分で管理する必要がある。
確認日

確認日：2026-10-06。公式サイト・公式GitHub・公式ドキュメントを中心に確認しました。開発が速いプロジェクトなので、機能や料金は変わる可能性があります。

誰が作ったか

開発元はNous Researchです。オープンウェイトの言語モデル群「Hermes」シリーズ（例：2025年8月公開のHermes 4）で知られる研究・開発組織です。ソースコードはGitHubのNousResearch/hermes-agentで公開されています。PythonとTypeScriptで書かれ、Linux・macOS・Windowsで動きます。

「Hermes」という名前の混同に注意

Nous Researchは「Hermes」という名前を2つの意味で使っています。両者は別物です。

Hermes（モデル）とHermes Agentの違い
Hermes（Hermes 4など）Hermes Agent
正体言語モデル（AIの頭脳そのもの）モデルを包んで動かすソフトウェア（エージェントの枠組み）
公開時期Hermes 4は2025年8月2026年2月
役割文章や推論を生成する記憶・スキル・ツール実行・メッセージ連携を担当する
モデルとの関係単体でも使えるHermesモデルに限らず、Claude・GPT・Gemini・ローカルモデルなどを差し替えられる

つまりHermes Agentを使うのに、Hermesモデルは必須ではありません。

Hermes＝頭脳、Agent＝それを包む枠

基本用語

用語意味
エージェントLLMが結果を見ながら、次に何をするかを自分で決めて実行を繰り返すもの。違いの詳細はAIエージェントとワークフローの違いを参照。
ハーネス（枠組み）モデルの外側で、記憶・ツール・権限・ループを受け持つ部分。Hermes Agentはこれにあたる。
スキル「このタイプの作業はこの手順でやる」と書いたMarkdownファイル（SKILL.md）。agentskills.ioというオープン標準に沿っている。
永続メモリ会話を閉じても残る記憶。利用者の好み、環境の情報、過去の失敗から得た教訓など。
ゲートウェイTelegram、Discord、Slack、WhatsApp、Signal、メールなどからエージェントに話しかけるための窓口プロセス。
ターミナルバックエンドコマンドを実行する場所。ローカル、Docker、SSH、Singularity、Modal、Daytonaなどから選ぶ。
サブエージェント親のエージェントが並行作業のために生み出す、別の会話・別の実行環境を持つ小さなエージェント。
MCP外部ツールをつなぐ共通規格。Hermes Agentも対応する。詳しくはMCP（Model Context Protocol）とは何か。

学習ループと全体像

学習ループの流れ

やさしく図解

Hermes Agentのいちばんの特徴は、使うほど手持ちの道具が増える仕組みです。公式の説明と解説記事によると、次のように働きます。

  1. 利用者が依頼し、エージェントがツールを使って作業する。
  2. 複雑な作業（目安として、ツール呼び出し5回以上と紹介する記事が多い）を終えると、うまくいった手順・落とし穴・確認方法をskill_manageツールでスキルとして書き残す。
  3. スキルは使うたびに修正される。メモリにも「この人はこうしてほしい」といった情報が足される。過去の会話は全文検索（FTS5）とLLM要約で引き出せる。
  4. 次に似た依頼が来たら、ゼロから考えず該当スキルを読み込んで進める。
育つのは外付けのノート。モデルはそのまま

スキルは3段階で少しずつ読み込まれます。最初は名前と説明の一覧だけ（約3千トークン）、必要なものだけ本文を読み、必要なときだけ付属ファイルを読みます。コンテキストを節約するための工夫です。なお、スキルの書き込みに人間の承認を挟むwrite_approvalの設定もあります。

全体の構成

構成要素と役割
層中身選べるもの
入口CLI、デスクトップアプリ、ゲートウェイTelegram、Discord、Slack、WhatsApp、Signal、メール。どこから話しても同じ記憶を共有する

チャットAIとの違い

やさしく図解

ChatGPTなどのチャットAIは、基本的に「会話の窓口」です。Hermes Agentは、モデルの周りに記憶・道具・常駐の仕組みを足したものです。ただし最近のチャットAIも、記憶機能やエージェント機能を持つものが増えており、境界は絶対的なものではありません。

チャットAIとHermes Agentの比較
観点普通のチャットAIHermes Agent
動く場所提供企業のクラウド自分のPC・VPS・クラウド環境（自己ホスト）
できること主に文章の生成と対話。機能は提供元が決めるコマンド実行、ファイル操作、ブラウザ操作、スケジュール実行など。ツールの追加は自由
記憶提供元の機能の範囲ローカルの~/.hermes/に保存。過去の会話の検索、利用者モデルの蓄積も
上達の仕方モデル自体の更新を待つ使ううちにスキルが増え、自分用に育つ
使うモデル基本はその会社のモデル自由に差し替えられる。ローカルモデルで完全オフラインも可能（コンテキスト64,000トークン以上が必要）
起動のきっかけ人間が話しかけたときcronによる定期実行やメッセージ着信でも動く
費用月額サブスクが中心本体は無料。モデルのAPI料金は別
責任の所在提供元が環境を管理設定・権限・保守・セキュリティは自分で管理

近い存在との違い

Claude Codeのようなコーディング用エージェントは、主に「いま開いているプロジェクトの作業」を支援します。Hermes Agentは、プロジェクトの枠を超えて常駐し、複数のチャット経路から呼び出され、経験を蓄積する個人用エージェントという位置づけです。同じ自己ホスト型・MIT・メッセージ連携のOpenClawとよく比較され、各種比較記事では「OpenClawは連携先の広さ、Hermesは記憶と自己改善の深さ」と整理されることが多いです。Claude Code側の拡張の仕組みはClaude Codeの拡張の全体像にまとめています。

使いどころの具体例

  • 個人の秘書として：スマホのTelegramから「昨日の議事録を整理して」と頼む。自宅や小さなVPSのHermesが作業し、結果を返す。
  • 定期作業：「毎朝8時にサーバーの状態をまとめて送って」と自然言語で頼むと、cronとして登録される。
  • 繰り返しの調査・運用：同種の作業が続くと、手順がスキル化されて速く安定する。
  • 並行作業：サブエージェントに調査を分担させる。
  • プライバシー重視の運用：ローカルモデル（Ollama・vLLM）と組み合わせ、データを外に出さずに動かす。公式FAQでは、設定したLLM提供元以外には通信せず、テレメトリも収集しないと説明している。

導入は公式のワンライナー（Linux・macOS・WSL2・Windows PowerShell・Termux向け）が用意されており、デスクトップアプリ版（macOS・Windows）もあります。

強み

強み内容
経験が蓄積するスキルと記憶により、使うほど自分の流儀に合っていく。
中身が読めるスキルはMarkdown、記憶は検索可能な形式なので、人間が確認・修正・バージョン管理できる。ブラックボックスの追加学習とは違う。
モデルに縛られないコマンド1つでモデルを切り替えられる。費用や性能の都合で乗り換えやすい。
データを手元に置けるローカルモデルと組み合わせれば完全オフライン運用も可能。
どこからでも使えるメッセージアプリ経由で、複数の経路でも同じ記憶を共有する。
自動実行と並列化cronスケジューラとサブエージェントを標準で備える。
安全のための仕組みがある危険なコマンドの承認、メッセージ連携のDMペアリング、コンテナ隔離などの仕組みがある。
オープンMITライセンスで、ソースも公開されている。agentskills.io標準やMCPにも対応し、外部のスキル資産を使える。

弱み・注意点

費用が見えにくい

本体は無料でも、モデルのAPI料金はかかります。学習の過程で背景のLLM呼び出しが増え、スキルが増えるほど「どのスキルを使うか」の判断にもトークンを使います。ゲートウェイ経由だと1ターンあたりの消費が大きいという解説もあります（CLIで6〜8千、ゲートウェイで1.5〜2万トークン程度という報告。環境依存の目安）。cronやサブエージェントは、寝ている間にも費用が発生します。個人の体験談として、再帰的なサブエージェント生成で一晩に約47ドルかかったという報告もあります。上限額やステップ数の制限を必ず設定してください。

本体は無料でも、動かすとお金がかかる

安全面のリスク

やさしく図解

エージェントは、コマンド実行やファイル操作などの強い権限を持ちます。さらに、自分が書いたスキルや記憶は、次回以降「信頼できる手順」として読み込まれます。そのため、Webページやメールに仕込まれた悪意ある指示（プロンプトインジェクション）が、1回限りで終わらず、保存されて残り続ける恐れがあります。解説記事では「保存ボタンのついたプロンプトインジェクション」とも表現されています。公式にも、危険コマンドの承認、DMペアリング、コンテナ隔離といった防御が用意されていますが、承認モードを「off」にすれば無効になり、設定次第で守りは弱くなります。攻撃全般の考え方はAIセキュリティ入門を参照してください。

スキルの劣化と思い込み

自己改善は「さっき動いたか」を基準に進むため、外部サービスの仕様が変わっても、古い手順を疑わずに使い続ける可能性があります。スキルが数百に増えると、探すコストも増え、間違ったスキルが選ばれる余地も広がります。

「さっき動いた」は「今も正しい」ではない

導入・運用の手間

  • 初期設定（モデル、ゲートウェイ、権限、バックエンド）に数時間かかるという比較記事が多い。ローカルモデルの用意が必要ならさらにかかる。
  • ローカルモデルは十分なコンテキスト長（64,000トークン以上）と性能が必要。結果の質はモデルとハードウェアに強く左右される。
  • スキルの数やエコシステムの成熟度は、先行する競合より小さいと評されることがある。専門的な用途は自作が必要になる場合がある。
  • オープンな課題（Issue）やPRが多く、開発が速い反面、仕様変更や不具合に付き合う必要がある。

対策の考え方

リスク対策の例
費用の暴走API側の利用上限、ステップ数制限、cron・サブエージェントの見直し、使うモデルの格下げ
スキルの劣化スキルをGitで管理、定期的に棚卸しして不要なものを削除、重要なものはスモークテスト
汚染・乗っ取り承認モードを手動またはsmartにしておく、Docker等の隔離環境で実行、write_approvalでスキル書き込みを承認制に、外部スキルはスキャン結果を確認
権限の過剰仕事用マシンの本体ではなく専用環境で動かす（公式ガイドにも専用の解説がある）

向く人・向かない人

向く人向かない人
自分用のAIを長く育てたい人設定やサーバー管理を一切したくない人
VPSやDockerなどの扱いに慣れている人1回きりの質問や文章作成で足りる人（チャットAIで十分）
データを自分の管理下に置きたい人、ローカルモデルを使いたい人費用の上限を決められない、または監視できない人
スマホのチャットから自分の環境に作業を頼みたい人機密性の高い環境に、権限の分離なしで入れようとする人
繰り返し作業を自動化したい人出力を必ず人間が検証する習慣のない人

はじめるなら、隔離された環境（Dockerなど）と少額の利用上限から試し、スキルの中身を見ながら育てるのが安全です。

よくある誤解

誤解実際
Hermes AgentはHermes（モデル）のことだ別物。Hermes Agentはモデルを包むソフトウェアで、中のモデルは差し替えられる。
自己改善とは、AIのモデル自体が賢くなることだモデルの重みは変わらない。変わるのは、書き溜めるスキルと記憶という「外付けのノート」。だから中身が読める。
オープンソースで無料だから、全部タダで使える本体は無料。モデルのAPI、VPS、Nous Portalのサブスク（有料プランあり）などは別料金。ローカルモデルでも電気代と機材がかかる。
自己ホストだから安全だデータの行き先は自分で決められるが、強い権限を持つ常駐エージェントの安全は自分で守る必要がある。
覚えさせたことは正しく残る誤った手順や古い手順も保存される。定期的に人間が見直す必要がある。
普通のチャットAIの上位互換だ用途が違う。単発の質問ではチャットAIの方が手軽で、設定も不要。

確認問題

Q1. Nous Researchの「Hermes 4」と「Hermes Agent」の違いを説明してください。

Hermes 4は言語モデル（AIの頭脳）、Hermes Agentはモデルを包んで記憶・スキル・ツール実行・メッセージ連携を担うエージェントの枠組み（ソフトウェア）。Hermes AgentはHermesモデルに限らず他社モデルやローカルモデルも使える。

Q2. Hermes Agentの「自己改善」で、実際に変わるものと変わらないものは何ですか。

変わるのはスキル（Markdownの手順書）と記憶という外付けのデータ。モデルの重みは変わらない。中身が読めるため、人間が確認・修正・削除できる。

Q3. 普通のチャットAIと比べたHermes Agentの特徴を、3つ挙げてください。

例：自分の環境で動く（自己ホスト）、コマンド実行やcronなどで自律的に動く、スキルと記憶が蓄積して自分用に育つ、モデルを自由に差し替えられる、などから3つ。

Q4. Hermes Agentが「無料」なのに、思わぬ費用が出る理由を2つ挙げてください。

本体が無料でもモデルのAPI料金は別。さらに、背景での学習処理、スキルの増加によるトークン消費、cronやサブエージェントによる夜間の自動実行などで、使っていない間も費用が発生する。VPSやサブスク費用が別にかかることもある。

Q5. 自己生成スキルが「通常のプロンプトインジェクションより厄介」といわれるのはなぜですか。また対策を2つ挙げてください。

悪意ある指示が一度保存されると、セッションが終わっても消えず、次回以降も信頼された手順として繰り返し読み込まれるから。対策例：承認モードを手動・smartにする、Dockerなどの隔離環境で動かす、スキル書き込みを承認制にする（write_approval）、スキルをGit管理して定期的に見直す。
