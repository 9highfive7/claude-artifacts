DeepSeek Harnessとは何か：すべてがプラグインのオープンソース・エージェント基盤

  • 確認日 2026-10-06
  • 分野 AI／開発
  • 対象バージョン 開発者プレビュー（v0.1系）

概要

3行でいうと
  1. DeepSeek Harness（コマンド名dsh）は、DeepSeek社が2026年8月に公開した、MITライセンスのオープンソース「エージェントハーネス」です。ハーネスとは、モデルを手元のファイル・ターミナル・ツール・会話履歴につないで動かす実行基盤のことです。
  2. 最大の特徴は「Everything is a Plugin」。モデルとの接続、ツール、セッション保存、サンドボックス、エージェントのループ（繰り返し処理）、画面までがプラグインで、設定から差し替えられます。
  3. 強みは差し替えやすさと記録の透明さ。弱みは開発者プレビューで破壊的変更が前提であること、第三者による監査がないこと、サンドボックスの範囲が限られることです。
はじめる前に

仕様は頻繁に変わるため、始める前に公式リポジトリを必ず確認してください。このノートの確認日は2026-10-06、対象は開発者プレビュー（v0.1系）です。

名前が曖昧だったため、候補を確認しました。本文の主題は候補Aの公式ハーネスです。

基本用語

用語意味覚えどころ
ハーネス（harness）モデルを「道具を使って作業するエージェント」にする周辺の仕組み。ツール呼び出し、権限、履歴の保存、ループ制御などを含むモデルが馬なら、手綱と馬具にあたる部分
dshDeepSeek Harnessのコマンド名とnpmパッケージ名（@deepseek-ai/dsh）deepseek harness の略
Cordisプラグインの組み立てを管理するメタフレームワーク。プラグインがサービス、型付きイベント、元に戻せる効果を共有コンテキストに提供するdshの下の層。プラグインの付け外しを面倒みる
プラグイン機能の最小単位。モデルアダプタ、ツール、セッション、サンドボックスなどがすべて該当この製品では「機能＝プラグイン」
プロファイル／バンドルプロファイルは起動構成の名前（web、headless、sdkなど）。バンドルは設定とコードをまとめた配布パッケージバンドルを積んだものがプロファイル
セッションイベントログ会話をチャット配列ではなく、追記専用の出来事の記録（JSONL）として残すもの「モデルに見えたものは必ず記録する」
ステップ／ターンステップは「モデルへの1回の要求とそのツール呼び出し」。ターンは0回以上のステップのまとまり1ターン＝複数ステップ
承認（approval）とサンドボックス承認は「ユーザーに確認するか」、サンドボックスは「触れる資源を物理的に制限するか」。別々の制御後述。混同しやすい

仕組みと全体像

Everything is a Plugin

やさしく図解

多くのコーディングエージェントは、中心のループ（モデルに聞く→道具を使う→結果を見る）が固定で、その周りに拡張を足す作りです。dshはこのループ自体を含めて、次のものをプラグインとして扱います。

要点：中心のループまで差し替えられる
  • モデルアダプタ（どのモデル、どのAPIにつなぐか）
  • ツール（ファイル編集、シェル、検索、スキル、計画、サブエージェントなど）
  • セッションの保存先、サンドボックス、ファイルシステム
  • エージェントのループ、複数エージェントの取りまとめ
  • 画面（UI）

Cordisのおかげで、プラグインは必要な依存関係を宣言するだけで起動順を手で書かずに済みます。外したときは、そのプラグインが登録したイベント、プロンプトの節、ツールの定義も自動で巻き戻ります。DataCamp記事はこれを「空間的な組み合わせ」と「時間的な組み合わせ」と呼んでいます（ここは記事側の整理で、公式用語かは未確認です）。

起動構成の積み重ね

公式のアーキテクチャ文書によると、起動時はプロファイルがバンドルを積み重ね、設定を「バンドルの設定 → プロファイルの修正 → ホーム（~/.dsh）の修正 → コマンドラインの上書き」の順に適用します。設定ファイルは既定で~/.dsh/settings.yaml、APIキーは別ファイル（~/.dsh/.credentials.yaml、ハンズオン記事より）に置かれます。

APIキーは設定ファイルとは別の場所

ツール実行の流れ

公式文書では、1ステップは「プロンプト組み立て → モデルへ要求 → 応答 → tools/pre-execute → 実行 → tools/post-execute → ログ」と進みます。実行の前後に割り込みポイントがあり、引数の検証、会社のルールの強制、出力の黒塗り、計測などをプラグインで差し込めます。ツールを実行するかどうかを決めるのはモデルだけでなく、別の方針（ポリシー）の層です。

実行の可否はモデルだけで決まらない

追記専用のセッションログ

やさしく図解

会話はチャット配列ではなく、追記専用のイベントログ（session.v1.jsonlのようにバージョン付き）で持ちます。公式文書の原則は「モデルに見えるものは、すべてログから再現できる」です。このおかげで、再開、分岐（fork）、検索、再生、評価がしやすくなります。ログの形式は版ごとに移行処理でつなぐ設計です。

原則：見えたものは全部ログに残る

モード中身向く場面

承認とサンドボックスの違い

やさしく図解

公式文書とHabr記事は、承認（ユーザーに確認が必要か）とサンドボックス（資源へのアクセスの制限）を別の制御として分けています。danger-full-accessのような権限プリセットは、この2つを独立に決めます。つまり、確認ダイアログがあってもファイルシステムの境界にはならず、サンドボックスがあっても本人の意思確認の代わりにはなりません。

既定では、ベース構成のプロファイルで新しいセッションはworkspace-writeプリセットになります。書き込みとシェルによる変更は作業ディレクトリと一時領域に限られますが、読み取りとネットワークは制限されません。プロセスの見え方はサンドボックスの実装次第です。

既定でも読み取りと通信は制限なし

具体例・使いどころ

始め方（導入と起動）

前提は Node.js です。公式サイトでは、デスクトップアプリ（macOSとWindows）か、次のコマンドでのWeb UI起動が案内されています。

npx @deepseek-ai/dsh web
# ブラウザで http://127.0.0.1:3080 が開く（既定）

ソースから動かす場合はpnpmを使います。

git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web

ハンズオン記事（deepakness.com）では、npxが最初は失敗したためソースからの導入に切り替え、約1分で起動できたと報告されています。起動後にAPIキーを求められ、SettingsのModelsから設定する流れです。公式サイトの説明では、モデルはDeepSeek-V4.1-Flashが前面に出ています。一方、第三者の検証記事ではV4-ProやV4-Flashの各版が使われていて、モデル名や版は記事ごとに違います。使う前に最新の一覧を確認してください。

npx が失敗したらソースから

使いどころ

  • 安いモデルで試す: DeepInfraの検証記事では、V4-Flash（入力100万トークンあたり0.08ドル／出力0.18ドル）で音声メモ連携の作業が39ステップ・約6分で約3セントでした。記事内の1事例で、一般化はできません。
  • モデルを途中で替える: 難しい推論は高価なモデル、機械的な作業は安価なモデル、とステップごとに割り当てる使い方が紹介されています。
  • 他のエージェントに任せる: サブエージェントとしてClaude CodeやCodexに仕事を渡し、外側のループはオープンウェイトのモデルで回す構成が可能と報告されています（DeepInfra記事）。
  • 自社のエージェント基盤として使う: ツール実行の前後に会社のルールを差し込めるため、プラットフォームチームが内製の基盤を作る用途に向きます（Wavectの評価）。
  • ベンチマークやエージェントの研究: ループやログを差し替えて、モデルとハーネスのどちらが結果に効いているかを比べる使い方です。
約3セントは1事例。一般化しない

強みと他ツールとの違い

強み

  • 差し替えやすさ: ループ、モデルアダプタ、保存先まで設定で入れ替えられる。フォークせずに済む。
  • モデルを選ばない: DeepSeek、Anthropic、OpenAI、OpenAI互換のエンドポイントにつなげる（DataCamp、DeepInfra、Wavectの記事）。
  • 記録の透明さ: 追記専用ログで、何がモデルに渡ったかを後から再現できる。
  • 見える化: トークン毎秒、キャッシュヒット、ツール呼び出し数、ステップ数などを画面に出す（ハンズオン記事）。実行トレースも公式サイトで案内されている。
  • オープンソース（MIT）: コードを読んで監査し、自分で拡張できる。
  • 非エンジニア向けの入口: 公式サイトはコード以外にも、文書、表計算、PDF、定期タスクの用途を挙げ、デスクトップアプリも用意している。

注意点・よくある誤解

弱みと注意点

項目内容対策の例
開発者プレビュー公式READMEが「互換性を壊す変更が入る」と明記。名称変更やセッションAPIの変更の例があるバージョンを固定。業務の本番には入れない
セキュリティ監査なし安全上の注意書きで、正式な監査を受けていないとされる（DataCamp）使い捨ての作業フォルダで試す
サンドボックスの範囲書き込みは制限するが、読み取りとネットワークは対象外（公式ドキュメント）外向き通信の制限、資格情報の分離を別途用意
間接プロンプトインジェクション2026年8月の論文（AI-Infra-Guardによる14,500回超の実験）で、攻撃手法によって成功率が異なると報告。例として、文字モードの「偽の完了」攻撃で17%、ファイルモードの不可視Unicode攻撃で25.5%。これは論文の特定条件での数字信頼できない内容と、機微な操作の間に制御を置く。承認を残す

視覚機能DeepSeekのモデルがテキストのみのため、画像を扱えないとの報告（ハンズオン記事）。使うモデル次第で変わる可能性画像が必要なら別のモデルを接続

よくある誤解

ここを間違えやすい
  • 「DeepSeekのモデル専用」ではない。OpenAI互換のエンドポイントにつなげられると複数の記事が報告しています（公式の対応モデル一覧までは確認できていません）。
  • 「ローカルだから安全」ではない。保存がローカルでも、外部のモデル提供元、Web検索ツール、第三者プラグインにはデータが送られうる、とDataCampが指摘しています。
  • 「サンドボックスがあるから何をされても平気」ではない。上記のとおり読み取りとネットワークは対象外です。「読み取り専用」とシステムプロンプトで指示するだけでは、OSレベルの強制になりません。
  • 「deepseek-harnessは1つ」ではない。Pythonの非公式ツール（候補B）が同名で、同じdshコマンド名を持ちます。
  • 「ハーネスはモデルの付属品」ではない。DataCampの記事は、ベンチマークの点数はモデルだけでなく使ったハーネスにも左右される、と述べています。これは同記事の主張で、特定の研究の引用はありません。

推測として書いておくと、プレビュー段階でのAPI変更が続く限り、ネット上の古い手順（モード名、コマンド、設定項目）は今の版と合わないことがあります。公式文書の日付を確認してください。

確認問題

Q1. DeepSeek Harnessの公式プロダクトと、同名の非公式ツールを見分けるポイントを2つ挙げてください。

公式はdeepseek-ai組織のリポジトリで、Node.js製のエージェント実行基盤（Web UI、CLI、デスクトップ）。非公式（HenryZ838978）はPython製で、DeepSeek V4のAPI挙動を検査するプロトコル層ツール。READMEが公式のforkではないと明記し、PyPIでの公開も公式より前。どちらもdshコマンド名を使うため、混同に注意。

Q2. 「Everything is a Plugin」で、固定されがちなどの部分までプラグインとして入れ替えられますか。3つ挙げてください。

例: エージェントのループ、モデルアダプタ、セッションの保存層（ほかにツール、サンドボックス、UIなど）。

Q3. 「承認」と「サンドボックス」の違いを説明してください。それぞれ片方だけだと何が足りませんか。

承認はユーザーに確認を求める仕組み、サンドボックスは触れる資源を制限する仕組み。承認だけでは、承認した後の操作は境界で止められず、サンドボックスだけでは本人の意思確認がない。さらに既定のサンドボックスは書き込みを主に制限し、読み取りとネットワークは制限しない。

Q4. 追記専用のセッションログにすると、チャット配列で持つ場合と比べてどんな利点がありますか。

モデルに見えたものをすべて再現できるため、再開、分岐、検索、再生、評価がしやすい。障害調査のための記録にもなる。

Q5. 職場で試すとき、最初に取るべき安全上の手順を3つ挙げてください。

例: (1) Minimalモードで使い捨ての作業フォルダから始める。(2) バージョンとプラグインを固定する。(3) 外向き通信の制限と資格情報の分離を別に用意し、破壊的な操作は承認制にする。信頼できない文書やリポジトリを読ませるときは特に注意する。
