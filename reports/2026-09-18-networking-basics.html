SECTION 1概要

SUMMARY
  • ネットワーク通信は役割ごとに層（レイヤー）で分担しており、その設計図が「OSI参照モデル」、実際に世界中で使われている実装が「TCP/IP」である。
  • 通信の相手を特定する住所が「IPアドレス」、住所をもとに荷物を届ける経路選びが「ルーティング」、人間が読める名前（ドメイン名）を住所（IPアドレス）に変換する仕組みが「DNS」である。
  • これらは独立した技術ではなく、Webページを1つ開くだけでも DNS → ルーティング → TCP/IP → OSI各層 という流れで連携して動いている。

SECTION 3仕組み・全体像

3-1. OSI参照モデル（7階層）

OSI参照モデルは、通信機能を7つの階層に分けて整理した「考え方の設計図」である。

1980年代、メーカーごとに独自仕様のネットワーク機器が多く相互接続が難しかったため、ISO（国際標準化機構）が共通の枠組みとして定めた。実際のプロトコル実装というより、通信をレイヤーごとに切り分けて理解・設計・トラブルシューティングするための「地図」として今も使われている。

層名称役割（自分の言葉で）代表的なプロトコル・機器
7アプリケーション層利用者が使うアプリの通信内容そのもの（Webページ取得、メール送信など）HTTP, HTTPS, SMTP, DNS
6プレゼンテーション層文字コードや暗号化・圧縮などデータの表現形式を整えるSSL/TLS（の一部）, 文字コード変換
5セッション層通信の開始から終了までの一連のやり取り（セッション）を管理するNetBIOS, セッション管理API
4トランスポート層データを確実に届けるか、速度優先で届けるかなど通信の品質を制御するTCP, UDP
3ネットワーク層異なるネットワーク間の経路を選び、宛先まで届ける（住所の役割）IP, ICMP, ルーター
2データリンク層同じネットワーク内の機器同士でデータをやり取りする（MACアドレスで識別）Ethernet, スイッチ
1物理層電気信号・光信号・電波など物理的にビットを伝送するLANケーブル, 光ファイバー, Wi-Fi電波, ハブ

覚え方としては「上位層（5〜7層）はデータの中身・意味を扱う」「下位層（1〜4層）は実際にデータを運ぶ仕組みを扱う」とざっくり分けると理解しやすい。

3-2. TCP/IPモデルとOSIとの対応

実際のインターネットで使われているのはOSIの7層ではなく、より簡略化された4階層の「TCP/IPモデル」である。OSIが理論的な設計図だとすれば、TCP/IPは実装に基づいた現実解といえる。

TCP/IPモデル対応するOSI層代表プロトコル
アプリケーション層アプリケーション層〜セッション層（5〜7層）HTTP, DNS, SMTP
トランスポート層トランスポート層（4層）TCP, UDP
インターネット層ネットワーク層（3層）IP, ICMP
ネットワークインターフェース層データリンク層〜物理層（1〜2層）Ethernet, Wi-Fi

3-3. TCPとUDPの違い

どちらもトランスポート層のプロトコルで、ポート番号を使ってアプリケーションを識別する点は共通だが、「確実さ」と「速さ」のどちらを優先するかが大きく異なる。

項目TCPUDP
接続の確立3ウェイハンドシェイクで接続を確立してから通信する接続確立をせずいきなりデータを送る
信頼性到達確認・再送・順序保証あり保証なし（届いたかどうかもわからない）
速度・オーバーヘッド制御が多い分やや遅い制御が少なく高速・低遅延
たとえ受領印をもらう書留郵便ポストに投函するだけの普通郵便
主な用途Webサイト閲覧、メール、ファイル転送動画・音声のストリーミング、オンラインゲーム、DNSの問い合わせ

3-4. IPアドレスの基礎（IPv4 / IPv6）

IPアドレスはネットワーク上の機器を一意に識別する「住所」である。現在主に使われているのは32ビットのIPv4（例：192.168.1.1）で、約43億個のアドレスしか作れず、スマートフォンやIoT機器の急増によって世界的にアドレスが枯渇しつつある。

この問題に対応するため128ビットのIPv6（例：2001:0db8:85a3:0000:0000:8a2e:0370:7334）への移行が進められており、実質無限に近い数のアドレスを扱える。

家庭や社内のLANでは、外部に直接公開されない「プライベートIPアドレス」（192.168.x.xや10.x.x.xなど）を使い、ルーターがNAT（Network Address Translation）という技術で1つの「グローバルIPアドレス」に変換してインターネットへ送り出すのが一般的である。

IPv6ではアドレスの数に余裕があるため、NATを使わずに端末へ直接グローバルなアドレスを割り当てる運用も広がっている。

3-5. サブネットマスクとCIDR表記

IPv4アドレスは32ビットで、「ネットワーク部」（所属するネットワークを示す部分）と「ホスト部」（そのネットワーク内の個々の機器を示す部分）に分かれる。この境界を示すのがサブネットマスクであり、/24のように「ネットワーク部が何ビットか」を書く表記法をCIDR（Classless Inter-Domain Routing）表記と呼ぶ。

EXAMPLE 例：192.168.1.0/24
  • 先頭24ビット（192.168.1の部分）がネットワーク部
  • 残り8ビットがホスト部 → 2^8 = 256通り（実際に機器へ割り当てられるのは、ネットワークアドレスとブロードキャストアドレスを除いた254個）
  • サブネットマスク表記では 255.255.255.0 と同じ意味になる

サブネッティングとは、1つの大きなネットワークをCIDRの数値を大きくする（ホスト部のビットを減らす）ことで、複数の小さなネットワークに分割する考え方である。例えば /24を/26にすると、256個の枠を4分割（各64個）でき、部署ごと・フロアごとにネットワークを分けたいときなどに使われる。

3-6. ルーティングの基本的な仕組み

同じネットワーク内の機器同士はスイッチなどを介して直接通信できるが、異なるネットワークへ送るときは「ルーター」が経路を選んで転送する。この経路選びをルーティングと呼ぶ。

  • ルーティングテーブル：ルーターや端末が持つ「この宛先ネットワークには、この次の転送先（ネクストホップ）へ送る」という経路の一覧表。
  • デフォルトゲートウェイ：ルーティングテーブルに一致する経路が見つからないとき、とりあえず送り先とする「出口」の機器。家庭用ルーターがこの役割を担うことが多い。
  • 最長一致（ロンゲストマッチ）：宛先IPアドレスに複数の経路が当てはまる場合、最もCIDRの数値が大きい（範囲が狭く、より具体的な）経路が優先される。

端末がパケットを送るときは、まず宛先IPアドレスが自分と同じネットワーク内かどうかを自分のIPアドレスとサブネットマスクから判断する。

同じネットワークならスイッチ経由で直接届け、異なるネットワークならデフォルトゲートウェイ（ルーター）へ送り、そこから先はルーター同士がルーティングテーブルを参照しながらバケツリレーのように次のルーターへパケットを転送していく。

3-7. DNSの仕組み（名前解決の流れ）

人間はexample.comのような名前でWebサイトを覚えるが、実際の通信にはIPアドレスが必要になる。この名前からIPアドレスへの変換を「名前解決」といい、DNS（Domain Name System）が担う。

  1. ブラウザがOSやプロバイダの「DNSリゾルバ（キャッシュサーバー）」にexample.comのIPアドレスを問い合わせる。
  2. リゾルバが答えをキャッシュしていなければ、まず「ルートDNSサーバー」に聞き、「.comを管理しているサーバーはこちら」と案内される。
  3. 次に「.com」を管理するTLD（トップレベルドメイン）サーバーに聞き、「example.comを管理しているのはこの権威DNSサーバー」と案内される。
  4. 最後に「権威DNSサーバー」（そのドメインの持ち主が管理するサーバー）に問い合わせ、実際のIPアドレスの回答を得る。
  5. リゾルバはこの結果をブラウザに返すと同時に、一定時間キャッシュしておき、次回以降の問い合わせを高速化する。

代表的なDNSレコードの種類：

レコード役割
Aレコードドメイン名をIPv4アドレスに対応づける（例：example.com → 93.184.216.34）
AAAAレコードドメイン名をIPv6アドレスに対応づける
CNAMEレコードあるドメイン名に別名（エイリアス）を付け、別のドメイン名を参照させる
MXレコードそのドメイン宛のメールを受け取るメールサーバーを指定する
NSレコードそのドメインを管理する権威DNSサーバーを指定する

SECTION 4具体例・使いどころ

CASE 1 Webページを開くまでの全体の流れ（総合例）
  1. ブラウザにhttps://example.comと入力する。
  2. DNSでexample.comが93.184.216.34というIPアドレスに解決される。
  3. 自分のPCは自分のIPアドレスとサブネットマスクから、宛先が別ネットワークだと判断し、デフォルトゲートウェイ（自宅ルーター）へパケットを送る。
  4. その後、インターネット上の複数のルーターがルーティングテーブルをもとにバケツリレー式にパケットを転送し、宛先サーバーへ到達する。
  5. TCPが3ウェイハンドシェイクで接続を確立し、HTTPS（アプリケーション層）のリクエストとレスポンスがやり取りされる。
  6. この一連の処理を、OSI参照モデルの各層（物理層でケーブルを流れる電気信号から、アプリケーション層のHTTPリクエストまで）が役割分担して実現している。
CASE 2 社内ネットワークをサブネットで分ける例

本社に 10.0.0.0/24（254台分）を割り当てていたが、部署が増えたため 10.0.0.0/26（営業部・約62台）、10.0.0.64/26（開発部・約62台）のように分割し、部署ごとにネットワークを分離してセキュリティやトラブル対応をしやすくする、といった使い方がある。

SECTION 5注意点・よくある誤解

CAUTION
  • 「OSI参照モデル＝実際に動いているプロトコル」ではない。OSIはあくまで通信を整理するための概念モデルであり、実際にインターネットで動いているのはTCP/IPモデルに基づく実装である。学習・議論のための「地図」として使うのが正しい使い方。
  • 5〜7層の境界はきっちり分かれていない。実際のプロトコル（HTTPSなど）はセッション管理や暗号化の役割も併せ持つことが多く、OSIの層に機械的に1対1で当てはめようとすると混乱しやすい。
  • 「サブネットマスクを大きくする＝ネットワークが大きくなる」は逆。CIDRの数値（例：/24 → /26）が大きくなるほど、ネットワーク部のビットが増え、1つのネットワークに入れる機器の数（ホスト部）は少なくなる。
  • ネットワークアドレスとブロードキャストアドレスは機器に割り当てられない。/24なら256個のうち、実際に端末へ割り当てられるのは254個である点を忘れがち。
  • デフォルトゲートウェイは「唯一の経路」ではなく「経路が見つからないときの最後の手段」。ルーティングテーブルに具体的な経路があればそちらが優先される。
  • DNSは1回の問い合わせで完結するとは限らない。キャッシュがなければルート→TLD→権威DNSと段階的に問い合わせるため、初回アクセスとキャッシュ済みアクセスでは応答速度が異なる。
  • UDPは「信頼性がない＝悪い」わけではない。動画配信やゲームのように多少のデータ欠落より速度を優先したい場面では、あえてUDPが選ばれる。

SECTION 6確認問題

問1.OSI参照モデルにおいて、IPアドレスを使った経路選択を担当するのは第何層か。

答えを見る

第3層（ネットワーク層）。IPやルーターが該当する。

問2.TCPとUDPのうち、3ウェイハンドシェイクを行い、データの到達を保証するのはどちらか。またその特性が向いている用途を1つ挙げよ。

答えを見る

TCP。到達確認・再送制御があり信頼性が高いため、Webサイト閲覧やファイル転送、メール送信などデータの欠落が許されない用途に向く。

問3.192.168.10.0/26 のネットワークで、ホスト部は何ビットあり、割り当て可能なホスト数（ネットワークアドレス・ブロードキャストアドレスを除く）はいくつか。

答えを見る

32ビット中26ビットがネットワーク部なので、ホスト部は 32 − 26 = 6ビット。2^6 = 64通りのうち、ネットワークアドレスとブロードキャストアドレスの2つを除いた62個が割り当て可能。

問4.自分の端末が持つルーティングテーブルに宛先ネットワークへの経路が見つからない場合、パケットはどこへ送られるか。

答えを見る

デフォルトゲートウェイ（多くの場合ルーター）へ送られ、そこから先の経路探索を委ねる。

問5.ブラウザで初めてexample.comにアクセスするとき、DNSの名前解決はどのような順番でサーバーに問い合わせるか、簡単に説明せよ。

答えを見る

DNSリゾルバ（キャッシュサーバー）に問い合わせ→キャッシュがなければルートDNSサーバー→「.com」を管理するTLDサーバー→example.comを管理する権威DNSサーバー、の順にたどってIPアドレスを取得する。
