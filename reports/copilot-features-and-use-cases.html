Copilotの機能と活用例：GitHub Copilotを中心に

  • 作成日 2026-10-05
  • 分野 AI
  • 確認日 2026-10-05（料金・プラン・上限は頻繁に変わる）

概要

3行でいうと
  1. 「Copilot」は1つの製品ではなく、GitHub Copilot（コードを書く人向け）、Microsoft 365 Copilot（Word・Outlookなどの仕事向け）、Microsoft Copilot（無料の汎用アシスタント）など別々の製品の総称である。
  2. GitHub Copilotは、入力中のコード補完から始まり、チャット、エージェントモード、Issueを渡すとPRまで作るコーディングエージェント（現在の公式名はcloud agent）、コードレビュー、CLIへと「任せる範囲」が広がってきた。
  3. 2026年6月からGitHub Copilotは「AI Credits」による従量課金に移行した。補完は無制限のままだが、チャットやエージェントの利用は枠を使い切ると止まるため、使い方と枠の管理が重要になった。
確認日 2026-10-05

料金・プラン・上限は頻繁に変わるため、利用前に必ず公式ページで再確認してください。

どのCopilotの話か

名前は同じで製品は別

同じ「Copilot」でも、使う場所・対象者・料金体系が違います。検索や社内で話が噛み合わないときは、まず「どのCopilotか」を確認するのが近道です。

製品主な対象動く場所情報の根拠にするもの
GitHub Copilot開発者VS Code・JetBrains・Visual Studio・Xcode、GitHub.com、CLI開いているコード、リポジトリ、Issue、PR
Microsoft 365 Copilot会社員（法人）Word・Excel・PowerPoint・Outlook・TeamsなどMicrosoft Graph経由で、本人が権限を持つメール・文書・会議・予定
Microsoft Copilot（無料アプリ等）個人・一般ユーザーWindows、Web、モバイルのアプリ主にWeb情報。会社のデータには自動では接続しない

このノートではGitHub Copilotを主役にし、後半でMicrosoft 365 Copilotを短く比べます。

基本用語

GitHub Copilotの用語

用語意味
コード補完（inline suggestions）エディタで入力中に、続きのコードを灰色で提案する機能。Tabで採用する。
Next Edit Suggestions次に直しそうな場所を予測して編集を提案する機能。補完と同じく有料プランで無制限。

cloud agent（旧coding agent）GitHub上のクラウド環境で動き、Issueを割り当てると作業してPRを作る。非同期で動く。

仕組みと全体像

任せる範囲の段階

GitHub Copilotの機能は、「人間がどこまで見ているか」で並べると理解しやすくなります。

任せるほど、人は最後にまとめて確認
機能動く場所人の関わり方向く作業
コード補完エディタ1回ごとに採用／不採用を決める定型コード、テストの雛形、繰り返しの記述
Copilot Chatエディタ・GitHub.com質問して答えを読む。必要なら貼り付けるコードの説明、エラーの原因調査、書き方の相談
エージェントモードエディタ（手元）差分とコマンド実行を見ながら承認複数ファイルにまたがる修正、ビルドエラーの解消
cloud agentGitHubのクラウドIssueに任せて、完成したPRをレビュー範囲の明確な小〜中規模のIssue、軽微なバグ修正
Copilot CLIターミナル計画モードで方針を確認、実行を承認、または-pで一発実行Git操作、スクリプト作成、PRの状態確認と修正
code reviewPR画面・エディタ・CLI指摘を読んで採用を判断人のレビュー前の一次チェック

IssueからPRまでの流れ

やさしく図解

cloud agentは、IssueをCopilotに割り当てると、GitHub上の隔離された環境でコードを読み、変更し、テストを走らせ、PRを出してレビューを依頼します。人の役目は、完成したPRを確認して、コメントで修正を指示するかマージすることです。最近は、PRを出す前に自分の変更をCopilot code reviewに通し、コードスキャン・シークレットスキャン・依存関係の脆弱性チェックも実行すると報告されています。

旧名はcoding agent。両方の名前で検索

確認日：2026-10-05。個人向けの価格・内訳はGitHub公式のプラン表を直接確認しました。Business／Enterpriseのクレジット額は、二次情報の報道に基づくため、必ず公式で確認してください。

プラン月額（目安）含まれる利用枠特徴

従量課金の考え方

やさしく図解

2026年6月1日に、以前の「premium request（プレミアムリクエスト）」の回数制から、AI Creditsによる使用量課金に変わりました。月額の基本料金は変わらず、補完とNext Edit Suggestionsはクレジットを消費しません。一方で、以前あった「枠を使い切ると安いモデルに切り替わって続けられる」仕組みはなくなり、ゼロになると追加購入か翌月まで待つ必要があります。

安いモデルへの自動切替はもう無い

具体例と使いどころ

活用例の一覧

「場面 → 頼み方の例 → 気をつける点」の形で整理します。

場面頼み方の例気をつける点
定型コードを書く（補完） 関数名とコメントだけ書いて、続きの提案をTabで採用する。例：「//日付文字列をYYYY-MM-DDに整形する」 提案は自信ありげでも間違うことがある。採用前に読む。補完は枠を消費しない。
知らないコードを読む（Chat） 該当部分を選択して「この関数が何をしているか、呼び出し元と合わせて説明して」 文脈に含めたファイルしか見えていないことがある。関連ファイルを明示する。
テストを足す（Chat／エージェントモード） 「この関数の境界値のテストを、既存のテストと同じ書き方で追加して。テストも実行して」 実装をなぞるだけのテストになりがち。期待値の正しさは人が確認する。
複数ファイルの修正（エージェントモード） 「APIのレスポンス型を変えたので、呼び出している箇所をすべて直して、ビルドが通るまで確認して」 ターミナル実行を伴うので、承認するコマンドを読む。範囲を絞って頼むとクレジットも節約できる。
小さなIssueを任せる（cloud agent） 受け入れ条件・対象ファイル・実行すべきテストをIssueに書き、Copilotに割り当てる 曖昧なIssueは的外れなPRになる。出てきたPRは人が必ずレビューする。大きな設計判断は任せない。
PRの一次チェック（code review） PRのレビュアーにCopilotを追加する 見逃しや的外れな指摘もある。人のレビューの代わりではなく、前段の補助と考える。
ターミナル作業（CLI） copilot -p "直近のコミットの変更内容を要約して"のように一発で実行。複雑な作業は計画モードで方針を見てから 自動実行に近いモードは、変更が速く進む分、取り消しやすい状態（ブランチを切る等）にしておく。
PRのつまずき解消（CLIの/pr） CIの失敗やレビュー指摘、コンフリクトの解消を、ターミナルから続けて依頼する push前に差分を確認する。ブランチの扱いはGitのブランチとは何かを参照。

Microsoft 365 Copilot：仕事の文書とメール

Microsoft 365 Copilotは、Word・Excel・PowerPoint・Outlook・Teamsの中で、メールの下書き、会議の要約、スプレッドシートの分析、スライド作成などを手伝います。最大の違いは、本人がアクセス権を持つ社内のメール・文書・会議のデータを根拠に答える点です。無料のMicrosoft Copilotは、会社のデータには自動では接続しません。

無料版は社内データにつながらない
項目GitHub CopilotMicrosoft 365 Copilot
主な成果物コード、PR、テスト文書、メール、要約、スライド
契約個人または組織でGitHubに契約Microsoft 365の基本ライセンスに追加するアドオン
料金の目安（確認日2026-10-05）10〜100ドル／月（個人）、19ドル・39ドル／ユーザー（組織）Copilot Businessは18ドル／ユーザー／月（年払い。通常は21ドルで、2026年12月までの割引価格）。一般向けの大企業用は月30ドル程度という報道もある
データの根拠リポジトリMicrosoft Graph（権限のある社内データ）

出典：Microsoft 365 Copilotの料金ページ（確認日2026-10-05）。Microsoft Learnの個別ページは今回の調査環境から取得できなかったため、製品の仕様は上記の公式ページと報道の要約に基づいています。

場面頼み方の例気をつける点
長いメールスレッドの把握（Outlook）「このスレッドの決定事項と未回答の質問を箇条書きにして」返信前に原文で事実を確認する。
会議後の整理（Teams）「議事録からアクション項目を担当者別に整理して」担当や期限の取り違えがないか、参加者が確認する。
資料の下書き（Word・PowerPoint）「この企画書をもとに、5枚のスライド構成案を作って」権限設定が甘いと、見せたくない文書を拾う可能性がある。共有範囲を整えておく。

Claude Codeとの使い分け

GitHub CopilotもClaude Codeも、ターミナルやCLIでエージェントとしてコードを読み書きできます。違いは、道具の置き場所と周辺の仕組みです。CopilotはGitHub（Issue・PR・レビュー）や各種エディタとの統合が強み、Claude CodeはCLAUDE.md・Skill・Hooks・MCPなど拡張を自分で組む自由度が強みです。たとえば「Issueを割り当ててPRで受け取る」流れはCopilotのcloud agentが得意で、手元で拡張や自動化を組み合わせるならClaude Codeが合います。拡張の考え方はClaude Codeの拡張の全体像を参照してください。エージェントの考え方はAIエージェントとワークフローの違いも参考になります。両者を併用する人も多く、排他的に選ぶ必要はありません。

注意点とよくある誤解

誤解しやすい点

誤解実際
「Copilotはひとつの製品」GitHub Copilot、Microsoft 365 Copilot、Microsoft Copilotなどは別製品。契約・料金・対象データが違う。
「Copilotの料金は月額固定」2026年6月からGitHub CopilotはAI Creditsによる従量課金。基本料金は同じでも、チャットやエージェントは使うほど減る。
「premium requestの回数が上限」premium requestの仕組みはAI Creditsに置き換わった。古い記事の「月300回」などの数字は現在の仕様ではない。
「補完も使うと枠が減る」補完とNext Edit Suggestionsは枠を消費しない（無料プランは回数制限あり）。
「エージェントが作ったPRはそのまま使える」必ず人がレビューする。セキュリティ面はAIセキュリティ入門のように、権限を最小にして確認する習慣が大切。
「coding agentという名前で探せばよい」最近の公式ドキュメントではcloud agentと呼ばれることがある。両方の名前で検索する。

安全面のポイント

  • 機密情報やトークンを、プロンプトやコードにそのまま貼らない。組織向けプランのポリシー設定を確認する。
  • エージェントに許可するコマンドや権限は必要最小限にする。
  • Microsoft 365 Copilotは本人の権限で社内データを探すため、そもそもの共有設定が広すぎると意図しない文書が要約に出る。導入前に権限を棚卸しする。
  • この領域は変化が速い。モデル名、プラン名、上限は数か月で変わるため、記事の日付を確認する。

確認問題

Q1. 「Copilotを導入したい」と言われたとき、最初に確認すべきことは何ですか。

どのCopilotか（GitHub Copilotか、Microsoft 365 Copilotか、無料のMicrosoft Copilotか）、誰が何に使うか。製品ごとに対象、契約、データの根拠が違うため。

Q2. エージェントモードとcloud agentの違いを、動く場所と人の関わり方で説明してください。

エージェントモードはエディタ（手元）で動き、人は差分やコマンドを見ながら承認する。cloud agentはGitHubのクラウドで非同期に動き、Issueを割り当てて、完成したPRをレビューする。

Q3. 2026年6月の課金の変更点を、補完とチャットの扱いの違いも含めて説明してください。

premium requestの回数制からAI Credits（トークン消費に応じた従量）に変わった。補完とNext Edit Suggestionsは枠を消費せず、チャットやエージェント、code reviewが消費する。枠がゼロになると有料機能は止まる。

Q4. cloud agentにIssueを任せるとき、Issueに何を書くと成功しやすいですか。2つ挙げてください。

受け入れ条件（何ができれば完了か）、対象のファイルや範囲、実行すべきテストなど。曖昧だと的外れなPRになりやすい。

Q5. Microsoft 365 Copilotが無料のMicrosoft Copilotと最も違う点は何ですか。

Microsoft Graphを通じて、本人が権限を持つ社内のメール・文書・会議などを根拠に答える点。無料版は主にWeb情報で、会社のデータには自動接続しない。
