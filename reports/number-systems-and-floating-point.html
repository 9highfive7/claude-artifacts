基礎理論：基数変換・補数・論理演算・浮動小数点

  • 作成日 2026-09-19
  • 分野 コンピュータサイエンス基礎

概要

3行でいうと
  1. コンピュータは内部で2進数（ビット列）しか扱えないため、基数変換は「人間が読む10進数」と「機械が扱う2進数・16進数」を橋渡しする、基礎理論すべての土台になる技術である。
  2. 負の数は符号を別枠で持つのではなく「2の補数」というビット列の工夫で表現され、これにより足し算の回路だけで引き算も実現でき、CPUの回路設計を単純化できる。
  3. 実数はIEEE754という「符号×仮数×基数^指数」の浮動小数点形式で表され、広い範囲の数値を少ないビット数で扱える代わりに、有限桁ゆえの丸め誤差・桁落ち・情報落ちが必ず発生する。

基本用語

用語意味
基数（radix / base）数を位取り記数法で表すときの基準となる数。2進数は基数2、10進数は基数10、16進数は基数16
位取り記数法各桁の位置（重み）に基数のべき乗を割り当てて数を表す方法。例：10進数の123は 1×10²+2×10¹+3×10⁰
補数（complement）ある数に足すと桁上がりして0（またはきりのよい数）になる数。負の数の表現や減算に利用する
1の補数2進数の各ビットを反転（0↔1）して得られる補数
2の補数1の補数に1を加えて得られる補数。現在のコンピュータで負の整数を表現する標準的な方式
論理演算真（1）・偽（0）の2値を対象に行う演算。AND（論理積）・OR（論理和）・NOT（否定）・XOR（排他的論理和）が基本
ビットマスク特定のビットだけを取り出したり書き換えたりするために、AND・OR・XORと組み合わせて使う定数のビット列
シフト演算ビット列全体を左または右にずらす演算。論理シフトと算術シフトの2種類がある
ド・モルガンの法則「AかつBの否定」は「Aの否定またはBの否定」に等しい、という論理演算の変形則。回路の簡略化や条件式の書き換えに使う
固定小数点数小数点の位置をあらかじめ固定して数値を表す方式。仕組みは単純だが表現できる範囲が狭い
浮動小数点数「符号×仮数×基数^指数」の形で数値を表し、指数部によって小数点の位置を動かせる（floatする）方式
IEEE754浮動小数点数の表現方法を定めた国際標準規格。現在のほとんどのコンピュータ・プログラミング言語が採用している
正規化浮動小数点数の仮数部を「1.〇〇×2^e」の形にそろえること。2進数では先頭が必ず1になるため、その1を省略して1ビット分を節約できる（ケチ表現）
バイアス（下駄履き表現）指数部に、実際の指数へある一定値（バイアス）を足した値を格納する方式。負の指数も0以上の整数として保存できる
丸め誤差・桁落ち・情報落ち・打ち切り誤差浮動小数点演算で生じる代表的な4種類の誤差。原因が異なるため区別して覚える必要がある

仕組み・全体像

3-1. 基数と基数変換

普段使う10進数は、各桁に「10のべき乗」の重みを持たせて数を表す位取り記数法である。同じ考え方を基数2・8・16に当てはめたものが2進数・8進数・16進数であり、コンピュータの内部では電圧の高低（ON/OFF）に対応する2進数がすべての基本になる。

人間には桁数が長くて読みにくい2進数を、3桁または4桁ずつまとめて短く表記するために8進数・16進数が使われる。

2進数 → 10進数（位取りで足し合わせる）

2進数の各桁に、右から順に2⁰, 2¹, 2², … の重みを掛けて合計すればよい。例えば2進数 1011001 を10進数に変換すると次のようになる。 

1011001(2)
= 1×2⁶ + 0×2⁵ + 1×2⁴ + 1×2³ + 0×2² + 0×2¹ + 1×2⁰
= 64    + 0    + 16    + 8     + 0    + 0    + 1
= 89

10進数 → 2進数（割り算法）

整数部分は、基数（2）で割り続けて商が0になるまで繰り返し、出てきた余りを「下から上（最後に出た余りが最上位桁）」の順に並べると2進数になる。10進数の89を例に手順をすべて示す。 

89 ÷ 2 = 44 … 余り 1
44 ÷ 2 = 22 … 余り 0
22 ÷ 2 = 11 … 余り 0
11 ÷ 2 =  5 … 余り 1
 5 ÷ 2 =  2 … 余り 1
 2 ÷ 2 =  1 … 余り 0
 1 ÷ 2 =  0 … 余り 1

余りを下から上に読む → 1011001(2)

確かに先ほどの2進→10進の計算結果89と一致しており、往復で検算できる。

10進小数 → 2進小数（掛け算法）

小数部分は、2を掛け続けて出てきた整数部分（0または1）を「上から下」の順に並べる。10進数の0.625を例にすると、次のようになる。 

0.625 × 2 = 1.25 → 整数部 1、残り 0.25
0.25  × 2 = 0.5  → 整数部 0、残り 0.5
0.5   × 2 = 1.0  → 整数部 1、残り 0（割り切れたので終了）

整数部を上から下に読む → 0.101(2)

検算：0.101(2) = 1×2⁻¹ + 0×2⁻² + 1×2⁻³ = 0.5 + 0 + 0.125 = 0.625 で一致する。

なお、10進小数はすべて割り切れて2進小数になるとは限らず、0.1のように2進数では無限に続く循環小数になってしまう値も多い（後述の丸め誤差の原因になる）。

0.1は2進数では割り切れない

2進数 ⇔ 16進数・8進数（区切って読み替える）

16 = 2⁴、8 = 2³ であるため、2進数を右端から4ビットずつ区切れば16進数の1桁に、3ビットずつ区切れば8進数の1桁に、それぞれ変換の割り算をせずに読み替えるだけで変換できる。10進数717を例に、2進・16進・8進の関係をすべて確認する。 

717(10) = 1011001101(2)

【16進数へ】右から4ビットずつ区切る（足りない上位は0で埋める）
  0010 1100 1101
   2    C    D
→ 2CD(16)

【8進数へ】右から3ビットずつ区切る（足りない上位は0で埋める）
  001 011 001 101
   1   3   1   5
→ 1315(8)

検算：2CD(16) = 2×16² + 12×16 + 13 = 512 + 192 + 13 = 717、1315(8) = 1×8³ + 3×8² + 1×8 + 5 = 512 + 192 + 8 + 5 = 717 となり、どちらも元の717と一致する。

16進数のA〜Fは10〜15を表すアルファベットである点も忘れずに押さえておきたい。

3-2. 補数

補数とは「ある数に足すと桁上がりしてちょうど0（またはきりのよい数）になる数」のことである。n進数には2種類の補数があり、2進数の場合はそれぞれ1の補数（各桁を基数−1から引いた数、2進数では単純にビット反転）と2の補数（1の補数に1を加えた数）と呼ぶ。

現在のコンピュータでは、負の整数を表現する方式としてほぼ例外なく2の補数が使われている。

2の補数を求める手順は次の2ステップだけである。8ビットで5の2の補数（＝−5を表すビット列）を求めてみる。

覚え方：全部反転して＋1
5 の2進数表現（8ビット）
    0 0 0 0 0 1 0 1

① 各ビットを反転する（0↔1）→ 1の補数
    1 1 1 1 1 0 1 0

② 1の補数に1を加える → 2の補数（-5を表す）
    1 1 1 1 1 0 1 1
なぜ2の補数で負数を表すのか

2の補数は「2ⁿ − x」という値に等しく、0を起点として負方向にxだけ進んだ位置に自然に対応する。この性質のおかげで、CPUは足し算のための加算回路だけで引き算（A − B = A + (−B)）も実現でき、減算専用の回路を別に用意しなくてよくなる。ハードウェアを単純化しつつ高速化できる、非常に実用的な工夫である。

2の補数を使った減算は、「引く数を2の補数にしてから足し、桁あふれ（キャリー）は単純に捨てる」だけで計算できる。8ビットで 11 − 5 を計算してみる。 

  11 の8ビット表現
      0 0 0 0 1 0 1 1
  -5 の2の補数（図2より）
  +   1 1 1 1 1 0 1 1
  ---------------------
  そのまま加算すると
    1 0 0 0 0 0 1 1 0      ← 9ビットになる

  8ビットからあふれた最上位の桁（キャリー）を捨てる
  ---------------------
  結果（8ビット）
      0 0 0 0 0 1 1 0      = 6

11 − 5 = 6 と正しく一致する。減算を「補数を作って足すだけ」の処理に統一できるのが2の補数の最大の利点である。

表現できる範囲に注意

nビットの2の補数表現で表せる整数の範囲は −2ⁿ⁻¹ 〜 2ⁿ⁻¹ − 1 であり、正と負で表現できる個数が非対称になる。8ビットなら −128〜127であり、最上位ビットが1で残りがすべて0の 10000000 は特別に−128を表す（対応する正の数+128は8ビットでは表現できない）。

3-3. 論理演算

論理演算は、真（1）・偽（0）の2値を対象にした演算で、AND（論理積）・OR（論理和）・NOT（否定）・XOR（排他的論理和）の4つが基本になる。コンピュータの内部では、これらをビット列の各桁ごとに適用する「ビット単位の論理演算」として利用されることが多い。

ABAND（A∧B）OR（A∨B）XOR（A⊕B）
00000
01011
10011
11110

NOTは1入力の演算で、0と1を反転させるだけである（NOT 0 = 1、NOT 1 = 0）。ANDは「両方とも1のときだけ1」、ORは「どちらか一方でも1なら1」、XORは「入力が異なるときだけ1（同じなら0）」という性質を持つ。

これらを8ビットのビット列 A = 10101100（10進数172）と B = 11001010（10進数202）に対して、桁ごとに適用すると次のようになる。

図3の検算と使いどころ

検算：AND(136) + OR(238) = 374 = A(172) + B(202) となり、桁ごとの計算が矛盾なく一致している。

ANDは「余分なビットを消すマスク処理」、ORは「特定のビットを立てる処理」、XORは「差分の検出やビット反転」によく使われる。

シフト演算

シフト演算はビット列全体を左または右にずらす演算で、論理シフトと算術シフトの2種類がある。論理シフトは符号を意識せず、あふれたビットを捨てて空いた桁に単純に0を詰める。

算術シフトは符号付きの数として扱うことを前提にしており、算術左シフトは論理左シフトと同じ（0を詰める）だが、算術右シフトは最上位の符号ビットをコピーして空いた桁に詰める（符号拡張）点が異なる。 

算術左シフト（×2 に相当）
   6 (00000110) を1ビット左へ → 00001100 = 12   （6×2=12）

算術右シフト（÷2 の切り捨てに相当、符号ビットを保持）
  -6 (11111010、2の補数8ビット) を1ビット右へ → 11111101 = -3   （-6÷2=-3）

算術左シフトはnビット左シフトで「×2ⁿ」、算術右シフトはnビット右シフトで「÷2ⁿ（切り捨て）」に相当する。ただし左シフトでは符号ビットの領域まで値があふれる「オーバーフロー」が起きる場合があるため注意が必要である。

ド・モルガンの法則

ド・モルガンの法則は、ANDとORの否定を相互に変形できることを示す法則で、次の2つの式で表される。 

NOT (A AND B)  =  (NOT A) OR  (NOT B)
NOT (A OR  B)  =  (NOT A) AND (NOT B)

「かつ」の否定は「それぞれの否定」の「または」になり、「または」の否定は「それぞれの否定」の「かつ」になる、と言い換えられる。プログラムの条件式を読みやすい形に書き換えたり、論理回路をNAND・NORだけで構成したりする際の基礎になる、試験でも頻出の法則である。

3-4. 浮動小数点数

小数を含む数値をコンピュータで表す方式には、大きく固定小数点数と浮動小数点数の2種類がある。

固定小数点数は、あらかじめ「整数部○ビット・小数部○ビット」のように小数点の位置を固定して数値を表す方式で、仕組みが単純で誤差の予測がしやすい反面、表現できる数値の範囲が狭い。

これに対して浮動小数点数は、数値を「符号 × 仮数 × 基数^指数」という形で表し、指数部の値によって小数点の位置を動かせる（floatする）ようにした方式である。少ないビット数でも、非常に大きい数から非常に小さい数まで幅広い範囲を扱えるのが最大の利点である。

IEEE754の構造

現在のほぼすべてのコンピュータ・プログラミング言語は、浮動小数点数の表現方式としてIEEE754という国際標準規格を採用している。ビット列は符号部・指数部・仮数部の3つに分かれており、代表的なのは32ビットの単精度と64ビットの倍精度である。

形式全体符号部指数部仮数部指数バイアス10進の有効桁数の目安
単精度（float）32ビット1ビット8ビット23ビット127約7桁
倍精度（double）64ビット1ビット11ビット52ビット1023約15〜16桁

値は次の式で求められる。 

値 = (-1)^符号 × 1.仮数部(2進数として) × 2^(指数部の値 − バイアス)

2進数を正規化すると先頭の桁は必ず1になる性質を利用し、その「1.」の部分は仮数部に格納せず省略する（ケチ表現）。

また指数部には、実際の指数にバイアス（単精度は127、倍精度は1023）を足した値を格納することで、負の指数も0以上の整数として保存でき、大小比較もビット列のまま行いやすくなる。

格納する指数＝実際の指数＋127

単精度で -6.25 を表現する手順を、途中式を省略せずに示す。 

① 絶対値6.25を2進数にする
   6      = 110(2)
   0.25   = 0.01(2)
   6.25   = 110.01(2)

② 正規化する（1.〇〇 × 2^e の形にそろえる）
   110.01(2) = 1.1001(2) × 2^2

③ 各部を求める
   符号部　: 負の数なので 1
   指数部　: 実際の指数2 + バイアス127 = 129 = 10000001(2)（8ビット）
   仮数部　: 1.1001 の小数点以下「1001」を左詰めし、残りを0で埋めて23ビットに
             1001 0000 0000 0000 0000 000（23ビット）

④ 32ビットに並べる
   符号(1) 指数部(8)  仮数部(23)
     1    10000001   10010000000000000000000

倍精度は単精度より指数部・仮数部が広いため、表現できる範囲が広く、精度（有効桁数）も高い。

指数部と仮数部のビットパターンには、通常の数値以外にも特別な意味を持つ組み合わせが定められている。指数部が全ビット0または全ビット1になる場合は、0・非正規化数・無限大・NaNなど特別な意味を持つ。

指数部仮数部意味
すべて0すべて0±0（符号部により+0と-0を区別）
すべて00以外非正規化数（0に極めて近い小さな値。暗黙の先頭ビットを1ではなく0として扱う）
すべて1すべて0±無限大（オーバーフロー時などに現れる）
すべて10以外NaN（Not a Number、非数。0÷0など定義できない演算の結果）

浮動小数点演算に伴う誤差

仮数部のビット数が有限である以上、浮動小数点数で表せる値は連続ではなく離散的であり、次のような誤差が原理的に避けられない。

  • 丸め誤差：仮数部の桁数に収まりきらない値を四捨五入・切り捨てなどで丸めることで生じる誤差。10進数の0.1は2進数では無限循環小数になり正確に表せないため、多くの言語で 0.1 + 0.2 が 0.3 ぴったりにならないのはこの丸め誤差が原因である。
  • 情報落ち：絶対値の差が非常に大きい数同士を加減算したとき、小さいほうの値が仮数部の桁数からあふれて結果にまったく反映されなくなる誤差。例えば「1.0×10⁸」に「1.0×10⁻⁸」を足しても、桁の差が大きすぎて結果が1.0×10⁸のまま変わらないことがある。
  • 桁落ち：絶対値がほぼ等しい数同士の減算（または符号が逆で絶対値がほぼ等しい数同士の加算）を行ったときに、上位の桁が打ち消し合って有効桁数が大きく減ってしまう誤差。例えば 1.000001 − 1.000000 = 0.000001 のように、有効桁の大部分が失われる。
  • 打ち切り誤差：円周率や数値積分・級数展開のように本来は無限に計算が続くものを、途中で打ち切ることによって生じる誤差。
桁落ちと情報落ちは原因が逆

桁落ちは「絶対値がほぼ等しい数どうしの引き算（打ち消し合い）」で起き、情報落ちは「絶対値の差が大きすぎる数どうしの足し算（小さいほうが埋もれる）」で起きる。どちらも「有効桁が足りなくなる」結果は似ているが、発生する場面が正反対である点を混同しやすいので注意したい。

具体例・使いどころ

具体例1　16進数はメモリアドレスや色コードの表記に使われる

デバッグ時に見るメモリアドレスや、Webページの色指定（#FF8800など）は16進数で表記される。2進数を4ビットごとに区切って読み替えられる性質のおかげで、人間にとって長い2進数を短く扱いやすい形に圧縮できるためである。

具体例2　ネットワークのサブネットマスクはAND演算そのもの

IPアドレスとサブネットマスクをビット単位でAND演算すると、そのIPアドレスが属するネットワークアドレスが求まる。「マスク（覆う）」という名前のとおり、ANDで不要な下位ビットを0に落とす典型的な使いどころである。

具体例3　権限やオプションのフラグ管理

OSのファイルパーミッションや、複数の設定項目をまとめて1つの整数で管理する「ビットフラグ」は、OR演算で特定のビットを立て（有効化）、AND演算で特定のビットだけを調べ、XORでトグル（反転）するという形で論理演算を活用している。

具体例4　金額計算に浮動小数点数を使ってはいけない理由

0.1や0.01のような10進小数の多くは2進数で正確に表現できず丸め誤差を含むため、金額計算をfloat/doubleで積み重ねると、わずかなズレが蓄積して合計額が1円単位でずれることがある。実務では、金額を整数（例：円ではなく銭単位の整数）で扱ったり、10進演算専用の型（多くの言語にある decimal 型など）を使ったりして、この誤差を避けるのが定石である。

注意点・よくある誤解

よくある誤解
  • 「1の補数と2の補数を混同する」誤り。 — 1の補数は単なるビット反転、2の補数はそれに+1したものである。現在のコンピュータの負数表現に使われているのは2の補数であり、1の補数には「+0と-0が別のビット列として存在する」という欠点がある。
  • 「2の補数の表現範囲は正負対称」だと思い込む誤り。 — nビットで表せる範囲は −2ⁿ⁻¹〜2ⁿ⁻¹−1であり、負の側が1つだけ多い（8ビットなら−128〜127）。最小値をそのまま符号反転しようとするとオーバーフローする点に注意。
  • 「論理右シフトと算術右シフトは同じ」だと思い込む誤り。 — 論理右シフトは空いた桁に必ず0を詰めるのに対し、算術右シフトは符号ビットを複製して詰めるため、負の数を扱うときの結果が異なる。符号なし整数には論理シフト、符号付き整数には算術シフトを使うのが基本である。
  • 「浮動小数点数は実数を正確に表せる」という誤解。 — 表現できるのはあくまで有限個の離散的な値であり、0.1のような一見きりのよい10進小数でも2進数では正確に表せず丸め誤差を持つ。等号（==）で浮動小数点数どうしを比較するのは避け、許容誤差（イプシロン）を使った比較をするのが定石である。
  • 「桁落ちと情報落ちは同じ現象」という誤解。 — 桁落ちは近い値同士の引き算で有効桁が消える現象、情報落ちは大きさの違いすぎる値同士の足し算で小さいほうが無視される現象であり、原因も対策も異なる。
  • 「ド・モルガンの法則はANDとORを単純に入れ替えるだけ」という誤解。 — ANDとORを入れ替えるだけでなく、内側の各項にもNOTを付け直す必要がある（NOT(A AND B) は (NOT A) OR (NOT B) であり、(NOT A) AND (NOT B) ではない）。

確認問題

Q1. 10進数89を、割り算法の手順（余りを書きながら）を使って2進数に変換せよ。

89÷2=44余り1、44÷2=22余り0、22÷2=11余り0、11÷2=5余り1、5÷2=2余り1、2÷2=1余り0、1÷2=0余り1。余りを下から上に読むと 1011001(2) になる（検算：64+16+8+1=89）。

Q2. 8ビットで5の2の補数を求め、その2の補数を使って「11−5」を筆算で計算せよ。

5=00000101をビット反転すると1の補数11111010、これに1を加えると2の補数11111011（-5）になる。11=00001011に11111011を加えると100000110（9ビット）となり、8ビットからあふれた最上位ビットを捨てると00000110=6が得られ、11-5=6と一致する。

Q3. ある8ビットの値から下位4ビットだけを取り出したい。どの論理演算と、どんなビット列（マスク値）を使えばよいか。

AND演算と、マスク値00001111（16進数で0x0F）を使う。ANDは「両方とも1のときだけ1」になる性質を持つため、上位4ビットは元の値に関わらず0になり、下位4ビットだけが元の値のまま残る。

Q4. IEEE754の単精度（32ビット）で -6.25 を表現するとき、符号部・指数部・仮数部はそれぞれどうなるか、途中式とともに答えよ。

6.25を2進数にすると110.01となり、正規化すると1.1001×2²になる。符号部は負の数なので1、指数部は実際の指数2にバイアス127を足した129=10000001（8ビット）、仮数部は正規化後の小数点以下「1001」を23ビットに0で埋めた10010000000000000000000になる。32ビット全体では 1 10000001 10010000000000000000000 となる。

Q5. 「桁落ち」と「情報落ち」の違いを、それぞれが発生する具体的な計算の例とともに説明せよ。

桁落ちは、絶対値がほぼ等しい数同士の減算（例：1.000001−1.000000=0.000001）で上位の桁が打ち消し合い、有効桁数が大きく減る現象である。情報落ちは、絶対値の差が非常に大きい数同士の加減算（例：1.0×10⁸に1.0×10⁻⁸を足す）で、小さいほうの値が仮数部の桁からあふれて結果にまったく反映されなくなる現象である。前者は「近い値の引き算」、後者は「大きさの違いすぎる値の足し算」で起きる点が異なる。
