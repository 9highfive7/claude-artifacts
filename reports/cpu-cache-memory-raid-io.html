概要

3行でいうと
  • コンピュータは、命令を解釈・実行する「CPU」、CPUと記憶装置の速度差を埋める「キャッシュメモリ」、データを保持する「主記憶・補助記憶」が階層的に連携して動いている。
  • 「RAID」は複数のディスクを束ねて速度や信頼性を高める技術、「入出力（I/O）」の仕組み（割り込み・DMA）はCPUがなるべく手をかけずに周辺機器とデータをやり取りするための工夫である。
  • これらは基本情報・応用情報技術者試験でも頻出の分野であり、「速いが高価で小容量」から「遅いが安価で大容量」へと段階的に構成される記憶階層の考え方が全体を貫く軸になる。

仕組み・全体像

3-1. CPUの構成要素

CPU（Central Processing Unit）は、伝統的な「コンピュータの五大装置」（入力・出力・記憶・演算・制御）のうち、演算装置と制御装置をひとまとめにした部品である。大きく次の3要素から成る。

  • 制御装置：主記憶から命令を取り出し、その命令を解読して、どの装置にどう動くよう指示するかを決める「司令塔」。デコーダが機械語命令を解読し、他の装置へ制御信号を出す。
  • 演算装置（ALU：Arithmetic Logic Unit）：四則演算や論理演算（AND・OR・比較など）を実際に行う回路。
  • レジスタ群：CPU内部にある超高速・極小容量の記憶回路。プログラムカウンタ（次に実行する命令のアドレスを保持）や命令レジスタ（取り出した命令そのものを保持）、汎用レジスタ（演算途中の値を保持）などの種類がある。

これらは主記憶よりもはるかに高速だが、非常に高価で容量が小さいため、必要最小限のデータしか置けない。この「速いが小さい」という制約こそが、後述するキャッシュメモリや記憶階層の考え方につながっていく。

3-2. 命令実行サイクルとパイプライン処理

CPUは、プログラムを構成する命令を「フェッチ（取り出し）→デコード（解読）→実行」という一連の流れで1つずつ処理し、これを高速に繰り返すことでプログラムを動かしている。より細かく分けると、次の5ステップとして説明されることが多い。

  1. 命令フェッチ：プログラムカウンタが指すアドレスから、主記憶にある命令を命令レジスタへ読み込む。
  2. 命令解読（デコード）：制御装置が命令の種類（加算・比較・分岐など）を解析する。
  3. 実効アドレス計算：命令が扱うデータの実際のメモリ番地を計算する。
  4. オペランド読み出し：計算したアドレスから、演算に必要なデータを読み込む。
  5. 命令実行：ALUが演算を行い、結果をレジスタや主記憶に書き戻す。

素朴な実装では1つの命令の5ステップがすべて終わってから次の命令のフェッチを始めるため、各回路が遊んでいる時間が多い。そこで、工場の流れ作業のように、複数の命令の異なるステップを同時並行で処理するパイプライン処理が使われる。

ある命令が「実行」段階にある間に、次の命令はすでに「デコード」段階、さらに次の命令は「フェッチ」段階、というように段階をずらして重ねることで、CPU全体としての処理能力（スループット）を高められる。

注意　パイプラインは止まることがある

ただし、パイプラインは万能ではない。分岐命令（if文など）の結果が確定するまで次に読み込む命令が決まらない「分岐ハザード」や、あるステップの結果を次のステップがすぐに使いたいのに間に合わない「データハザード」などにより、パイプラインが一時的に止まる（ストールする）ことがある。

3-3. クロック周波数・マルチコア・CISC/RISC

クロック周波数は、CPU内部の全回路が同期して動くための「リズム」を刻む回数で、単位はHz（ヘルツ）である。

同じ設計のCPUであれば周波数が高いほど1秒あたりの処理回数は増えるが、2000年代半ば以降は周波数を上げるほど消費電力・発熱が急増する物理的な壁にぶつかり、単純な高周波数化による性能向上は頭打ちになった。

そこで主流になったのがマルチコア化である。1つのチップに演算コアを複数搭載し、コアごとの動作周波数は抑えつつ、複数の処理を並列に実行することで、消費電力を抑えながら全体の処理能力を高める設計へとシフトした。ただし、マルチコアの恩恵を受けるには、ソフトウェア側が処理を複数のコアに分けられるように作られている必要がある。

CPUの命令セット（設計思想）には大きく2つの系統がある。

項目CISC（Complex Instruction Set Computer）RISC（Reduced Instruction Set Computer）
命令の性格1つの命令で複雑な処理をまとめて実行できる、種類の多い命令セット単純で実行時間がそろった命令だけに絞った命令セット
狙い少ない命令数でプログラムを書けるようにする命令を単純化してパイプライン処理などの高速化技術を活かしやすくする
代表例Intel/AMDのx86系CPUArm系CPU（スマートフォンや近年のPC・サーバー向けCPUに多い）

近年はCISCのx86系にもRISC的な内部設計（複雑な命令を内部で単純な命令に分解して実行するなど）が取り入れられ、RISC系にも機能拡張が進んでおり、両者の違いは以前ほど明確ではなくなってきている。

3-4. キャッシュメモリの目的と階層構造

CPUの処理速度は年々向上してきたが、主記憶（DRAM）のアクセス速度はそれほど速くなっておらず、CPUと主記憶の間には大きな速度差がある。CPUが命令やデータを取りに行くたびに主記憶へアクセスしていては、せっかくの高速なCPUが待たされてばかりになってしまう。

この速度差を埋めるために置かれる、小容量・超高速な記憶装置がキャッシュメモリである。

キャッシュメモリはCPUに近いほど高速・小容量、遠いほど低速・大容量という段階（L1・L2・L3）に分けて構成されるのが一般的である。

階層位置づけ速度・容量の目安
L1キャッシュ各CPUコアの内部に個別に搭載。最も高速で最も小容量数十KB程度、アクセスはほぼ1〜数クロック
L2キャッシュコアごと、または少数のコアで共有数百KB〜数MB程度
L3キャッシュCPUチップ内の全コアで共有されることが多い数MB〜数十MB程度。L1・L2よりは低速だが主記憶よりずっと高速

CPUはまずL1を探し、なければL2、それでもなければL3、最後に主記憶という順に探しに行く。目的のデータがキャッシュに見つかることを「ヒット」、見つからず主記憶まで探しに行くことを「ミス」と呼ぶ。

3-5. ヒット率と実効アクセス時間の計算

キャッシュメモリがどれだけ効果を発揮しているかは、「ヒット率」と、それをもとに計算する「実効アクセス時間」で評価する。実効アクセス時間は次の式で求める。

計算式

実効アクセス時間 ＝ キャッシュのアクセス時間 × ヒット率 ＋ 主記憶のアクセス時間 × (1 − ヒット率)

たとえば、キャッシュメモリのアクセス時間が10ナノ秒、主記憶のアクセス時間が100ナノ秒、ヒット率が90%（0.9）だとすると、実効アクセス時間は次のように計算できる。 

実効アクセス時間 = 10ns × 0.9 + 100ns × (1 − 0.9)
             = 9ns + 10ns
             = 19ns

キャッシュが無ければ毎回100ナノ秒かかるところ、ヒット率90%のキャッシュがあるおかげで平均19ナノ秒まで短縮されていることが分かる。基本情報・応用情報技術者試験では、この式を使って「ヒット率を求めよ」「実効アクセス時間を比較せよ」という形式で頻出する。

3-6. キャッシュの書き込み方式

CPUがキャッシュ上のデータを書き換えたとき、その変更をいつ主記憶へ反映するかによって、2つの方式がある。

方式仕組み長所・短所
ライトスルー方式キャッシュへの書き込みと同時に、必ず主記憶にも書き込むキャッシュと主記憶の内容が常に一致し単純・安全。ただし書き込みのたびに低速な主記憶へのアクセスが発生し、書き込み性能は向上しない
ライトバック方式書き込みはまずキャッシュだけに行い、「主記憶に未反映」の印を付けておく。該当データがキャッシュから追い出されるタイミングなどでまとめて主記憶に書き戻す読み書きともに高速。ただしキャッシュと主記憶の内容が一時的に食い違うため、制御が複雑になる

3-7. 主記憶・補助記憶と記憶階層全体

主記憶（メインメモリ／RAM）は、CPUが実行中のプログラムやデータを直接読み書きする記憶装置で、電源を切ると内容が消える「揮発性」の性質を持つ。RAMには主に2種類がある。

種類特徴主な用途
DRAM（Dynamic RAM）コンデンサに電荷を蓄えてデータを保持するため、放っておくと自然放電で内容が消える。定期的に再書き込み（リフレッシュ）する必要がある。構造が単純で1ビットあたりの回路規模が小さく、大容量・低コストにしやすい主記憶（メインメモリ）
SRAM（Static RAM）フリップフロップ回路でデータを保持するためリフレッシュが不要で、DRAMよりも高速。ただし1ビットあたりの回路規模が大きく高コストになりやすいCPU内のキャッシュメモリ（L1〜L3）

一方補助記憶（外部記憶）は、SSDやHDDのように電源を切ってもデータが消えない「不揮発性」の記憶装置で、主記憶よりも低速だが大容量・低コストであり、OSやアプリケーション、ファイルなどを長期的に保存する役割を担う。プログラムを実行するときは、補助記憶に保存されているデータを一旦主記憶へ読み込んでからCPUが処理する、という流れになる。

記憶階層のポイント

ここまで見てきたレジスタ・キャッシュ・主記憶・補助記憶は、図2のピラミッドのように「上ほど高速・小容量・高価、下ほど低速・大容量・安価」という一貫した設計思想でつながっている。

すべてを高速なSRAMだけで作れれば理想的だが、コストの制約上それは非現実的であるため、段階的に速度とコストのバランスを取っているのが記憶階層の本質である。

3-8. RAIDの仕組み

RAID（Redundant Arrays of Inexpensive/Independent Disks）は、複数台のディスク（HDD・SSD）を組み合わせて1つの論理的なドライブとして扱う技術で、読み書きの高速化や、一部のディスクが故障してもデータを失わないようにする耐障害性の向上を目的とする。代表的なレベルは次のとおり。

レベル仕組み耐障害性容量効率（n台構成）
RAID 0（ストライピング）データを分割し、複数ディスクに分散して同時に読み書きするなし。1台でも故障すると全データが失われる100%（冗長データを持たないため最大）
RAID 1（ミラーリング）同じデータを2台以上のディスクに複製して書き込む高い。1台故障してももう1台がそのまま使える50%（2台構成の場合。台数を増やしても使える容量は1台分のまま）
RAID 5（分散パリティ）データとあわせて、誤り訂正用の「パリティ」情報を計算し、全ディスクに分散して書き込むディスク1台までの故障に耐えられる(n−1)/n（例：4台構成なら75%）
RAID 6（二重分散パリティ）RAID5の仕組みに加え、パリティを2系統計算して分散配置するディスク2台までの同時故障に耐えられる(n−2)/n（例：4台構成なら50%）

3-9. 入出力インタフェース

CPU・メモリと周辺機器（ストレージ、マウス、外部モニタなど）を接続する規格を入出力インタフェースと呼ぶ。データを複数ビット同時に送る「パラレル方式」と、1ビットずつ順番に送る「シリアル方式」があるが、配線の複雑さや信号の干渉（クロストーク）の問題から、現在は高速化しやすいシリアル方式が主流になっている。

規格主な用途特徴
USB（Universal Serial Bus）マウス・キーボード・外付けストレージなど汎用の周辺機器接続ハブ経由で多数の機器を接続可能、電源を入れたまま抜き差しできるホットプラグに対応
SATA（Serial ATA）HDD・SSDの接続従来のパラレル方式だったATA（IDE）をシリアル化した規格。PC内部のストレージ接続で長く主流だった
PCIe（PCI Express）グラフィックボード、NVMe SSD、拡張カードなどの接続「レーン」と呼ぶ伝送路を複数束ねることで高速な転送を実現。世代・レーン数によって帯域が変わる

なお、近年主流のNVMe SSDはSATAではなくPCIeに直結する規格で、SATA接続のSSDよりも大幅に高速なため、新しいPCでは補助記憶の接続方式そのものがSATAからPCIe（NVMe）へ置き換わりつつある。

3-10. 割り込み処理とDMA

周辺機器（キーボード、ディスク、ネットワークカードなど）とのデータのやり取りは、CPUの処理速度に比べてずっと低速である。この速度差を効率よく扱うための仕組みが割り込みとDMAである。

割り込みとは、実行中の処理を一時的に中断し、より優先度の高い処理（周辺機器からの通知への対応など）を先に行う仕組みである。CPU外部からの信号によって発生する「ハードウェア割り込み」（周辺機器やタイマーからの通知など）と、実行中のプログラム自体が引き起こす「ソフトウェア割り込み」（ゼロ除算などのエラー発生時や、OSの機能呼び出しなど）に大別される。

割り込みが発生すると、CPUは現在の処理状態を保存し、専用の処理（割り込みハンドラ）を実行したあと、元の処理に戻る。

もし周辺機器とのデータ転送を、CPUが1バイトずつ自分で読み書きして行っていたら、CPUはその間ずっと転送作業に拘束されてしまう。そこで使われるのがDMA（Direct Memory Access）である。DMAでは、CPUの代わりに「DMAコントローラ（DMAC）」という専用回路が、周辺機器と主記憶の間のデータ転送を代行する。

  1. CPUはDMAコントローラに対して、転送元・転送先のアドレスと転送量を指示するだけで、以降の転送処理からは解放される。
  2. DMAコントローラが周辺機器と主記憶の間で直接データをやり取りする（CPUを経由しない）。
  3. CPUはその間、別の処理を並行して実行できる。
  4. 転送が完了すると、DMAコントローラが割り込みを発生させてCPUに完了を通知する。

具体例・使いどころ

具体例1　アプリを起動したときの記憶階層の動き

アプリのアイコンをクリックすると、補助記憶（SSD）に保存されていたプログラムが主記憶（RAM）へ読み込まれる。実行中、CPUはよく使う命令やデータをL1〜L3キャッシュに保持し、ヒット率が高いほどサクサク動く体感になる。

RAMが少なくアプリを大量に開いていると、主記憶に収まりきらないデータが補助記憶へ一時的に退避（スワップ）され、動作が急に重くなる、というのも記憶階層の速度差が体感できる代表例である。

具体例2　用途に応じたRAIDレベルの選択

個人のバックアップ用途で単純に冗長性がほしいならRAID1、動画編集用など読み書き速度を最優先したいがデータ消失のリスクを許容できるならRAID0、ファイルサーバーやNASのように容量効率と一定の耐障害性を両立したいならRAID5、より重要なデータでディスク故障の同時発生にも備えたいならRAID6、というように用途とリスク許容度に応じて使い分ける。

企業のデータベースサーバーでは、RAID1とRAID0を組み合わせたRAID10（速度と冗長性の両立）もよく使われる。

具体例3　大容量ファイルのコピーとDMA

数GBの動画ファイルをコピーしている間もマウスやキーボードの操作が問題なくできるのは、ストレージと主記憶の間のデータ転送をDMAコントローラが担当し、CPUが転送作業そのものに縛られていないためである。CPUは転送の開始を指示したあと、転送完了の割り込みが来るまで別の作業（画面描画やユーザー操作への応答など）を続けられる。

注意点・よくある誤解

よくある誤解
  • 「クロック周波数が高い＝CPUが速い」とは限らない。 — 1クロックあたりに処理できる命令数（IPC）やコア数、命令セットの効率によって実際の性能は変わるため、周波数だけで単純比較はできない。
  • 「キャッシュを増やせば増やすほど無限に速くなる」わけではない。 — プログラムがアクセスするデータには偏り（局所性）があり、ヒット率の向上には限界がある。またキャッシュを大きくするほど1回あたりのアクセス時間自体は延びる傾向があり、単純な大容量化が常に得とは限らない。
  • SRAMとDRAMの用途を逆に覚えやすい。 — 「高速だが高コストなSRAM＝キャッシュ」「大容量・低コストだがやや低速なDRAM＝主記憶」という対応を混同しないよう注意する。
  • RAIDはバックアップの代わりではない。 — RAIDが守るのは「ディスク故障による可用性の低下」であり、誤削除・ランサムウェア・火災などデータそのものが失われるリスクには対応できない。別途バックアップが必須。
  • RAID0は「RAID」という名前でも冗長性がない。 — 高速化だけが目的で、1台でも故障すると全データを失う点を初学者は見落としやすい。
  • RAID5・6は書き込み時にパリティ計算のオーバーヘッドが発生し、単純なストライピングより書き込みが遅くなる（ライトペナルティ）。 — 「冗長性があるのに速度は落ちない」という誤解に注意。
  • DMAを使っても割り込みが完全になくなるわけではない。 — 転送中はCPUを介さないが、転送完了の通知には結局割り込みを使う。「DMA＝割り込みゼロ」という誤解に注意。

確認問題

Q1. CPUが命令を実行する基本的な流れを、フェッチ・デコード・実行という言葉を使って説明せよ。

プログラムカウンタが指すアドレスから命令を取り出す「フェッチ」、取り出した命令の内容を解読する「デコード」、解読結果に基づきALUなどが実際に処理を行う「実行」の順に処理が進み、これを高速に繰り返すことでプログラムが動く。

Q2. キャッシュメモリのアクセス時間が10ナノ秒、主記憶のアクセス時間が100ナノ秒、ヒット率が90%のとき、実効アクセス時間は何ナノ秒か。

実効アクセス時間 = 10ns × 0.9 + 100ns × (1 − 0.9) = 9ns + 10ns = 19ナノ秒。

Q3. RAID1とRAID5は、それぞれディスク何台の故障まで耐えられるか。また、容量効率（実際に使える容量の割合）が高いのはどちらか。

RAID1は1台（ミラーリングしているディスクのうち1台）の故障まで耐えられ、容量効率は2台構成なら50%。RAID5も1台の故障まで耐えられるが、パリティを分散して持つため容量効率は(n−1)/n（例：4台構成で75%）となり、一般にRAID1よりRAID5の方が容量効率が高い。

Q4. ライトバック方式のメリットと、それに伴うデメリットを1つずつ挙げよ。

メリット：書き込みのたびに低速な主記憶へアクセスする必要がなく、書き込み性能が向上する。デメリット：キャッシュと主記憶の内容が一時的に一致しなくなるため、データの整合性を保つための制御が複雑になる。

Q5. DMAを使うことで、CPUを介さない場合と比べてどのようなメリットが得られるか、DMAコントローラの役割とあわせて説明せよ。

周辺機器と主記憶の間のデータ転送をDMAコントローラが代行することで、CPUは転送元・転送先・転送量を指示するだけでよくなり、転送処理自体に時間を取られずに別の処理を並行して実行できる。転送が完了すると、DMAコントローラが割り込みでCPUに完了を通知する。
