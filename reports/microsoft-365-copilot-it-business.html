Microsoft 365 Copilot の活用：IT企業の業務とCopilot Studioのエージェント

  • 作成日 2026-10-06
  • 分野 AI

概要

3行でいうと
  1. Microsoft 365 Copilot は、Teams・Outlook・Word・Excel・PowerPoint などの業務アプリに入ったAIで、会議・メール・文書・データを横断して下書き、要約、分析を手伝う。
  2. 自分専用や小規模チーム向けは Agent Builder、部署や会社全体、社外向け、業務システム連携には Copilot Studio と、エージェントは規模と統制の必要度で作り分ける。
  3. Copilot は「その人が見られるデータ」を使うため、導入前の権限整理（過剰共有の是正）と、エージェントの管理ルール作りが成否を分ける。

確認日：2026-10-06。機能名・提供状況・料金は変わりやすいため、導入前に公式ページで再確認してください。GitHub Copilot 中心の話は Copilotの機能と活用例：GitHub Copilotを中心に を参照。このノートは Microsoft 365 Copilot（Word・Teams・Outlook などに入るAI）に絞ります。

仕組みと全体像

Copilot の動き方

Copilot は、依頼を受けると Microsoft Graph から本人が見られる範囲のデータを集め、大規模言語モデルに渡して回答を作る。「新しい権限は与えない」のが基本原則で、本人がアクセスできないSharePointサイトやメールボックスの内容は出てこない。裏返すと、本人が見られるが見られるべきでないデータ（過剰共有）はそのまま出てしまう。

権限は足さず、削りもしない

エージェントは、ワークフロー、コネクタ、REST API、MCP サーバー、他のエージェントを呼び出して、実際に業務システムを操作できる。MCP の基礎は MCP（Model Context Protocol）とは何か、エージェントと固定手順の違いは AIエージェントとワークフローの違い を参照。標準ハーネスは前者の「決めた手順に沿う」側、GitHub Copilot ハーネスは後者の「自分で次の手を決める」側に近い。

導入と運用

権限整理が先

やさしく図解

導入前に、SharePoint の共有設定を点検する。Microsoft は、パイロット、展開、運用の順で進め、最初に過剰共有を是正することを勧めている。主な手段は次のとおり。

検索から外すのは応急処置。権限は直らない
手段役割
SharePoint Advanced Managementサイトの権限レポート、サイトアクセスレビュー
Restricted Content Discovery指定サイトを Copilotや組織内検索の対象から外す。直接のアクセス権は変えない応急処置
Microsoft Purview（秘密度ラベル、DLP）機密データの分類、Copilot の参照対象からの除外、監査

AI特有のリスク（プロンプトインジェクション、情報漏えいなど）の全体像は AIセキュリティ入門 — 守る側のための教科書 が詳しいので、ここでは繰り返さない。

エージェントの管理

Agent Builder 製は Microsoft 365 管理センターの「Copilot」>「エージェント」で、一覧、有効化・無効化、割り当て、ブロック、削除ができる。Copilot Studio 製は Power Platform 管理センターで、環境、コネクタ、DLP、公開ワークフロー、利用分析を管理する。組織のアプリカタログへの公開には管理者の承認が要る。

注意点とよくある誤解

誤解しやすい点

誤解実際
Copilot が勝手に社外へデータを送るCopilot は本人の権限内のデータを参照する。問題になりやすいのは社内の過剰共有のほう
Copilot Studio は専門のプログラマーしか使えないローコードで、メーカー層が主な対象。ただし本番運用はテスト、環境分離、レビューが必要
Agent Builder と Copilot Studio は別物で移行できないAgent Builder のエージェントは Copilot Studio にコピーできる
入れれば自動で生産性が上がる頼み方、利用シーンの設計、研修がないと使われない。まず業務を絞ったパイロットから
AIの回答はそのまま使える誤りや根拠の取り違えがありうる。顧客向け文書や数値は必ず人が確認する
GitHub Copilot と同じもの名前は似ているが別製品。ただし Copilot Studio のハーネスの1つに GitHub Copilot ハーネスがあり、境界は混同しやすい

覚え方

「Agent Builder は自分と仲間、Copilot Studio は部署から社外まで」と、公開範囲で区別する。Copilot の安全性は「本人の権限＝Copilotの権限」と覚え、導入前にまず権限を整える。

確認問題

Q1. Microsoft 365 Copilot が回答に使うデータの範囲は、どのように決まるか。

本人がアクセスできる Microsoft 365 内のデータ（Microsoft Graph 経由）に限られる。新しい権限は与えられない。

Q2. 自分のチームのSharePoint資料に答えるFAQエージェントを素早く作りたい。まず使うべきツールは何か。

Agent Builder。個人や小規模チーム向けの軽量Q&Aに向く。後から Copilot Studio にコピーして拡張できる。

Q3. Copilot Studio の3つのハーネスを挙げ、複数ステップで判断が要る業務に向くものを答えよ。

GitHub Copilot ハーネス、標準ハーネス、Copilot Chat ハーネス。判断が要る複数ステップの業務には GitHub Copilot ハーネスが向く。

Q4. 導入前に過剰共有を是正する理由と、応急処置になる機能を1つ挙げよ。

本人が見られるが見られるべきでないデータが、Copilotの回答に出てしまうため。応急処置として Restricted Content Discovery（指定サイトをCopilotの検索対象から外す）などがある。

Q5. 外部の顧客向けに公開し、CRMとも連携するエージェントに適したのはどちらか。

Copilot Studio。広い公開範囲、外部システムとのコネクタ連携、ライフサイクル管理に対応する。
