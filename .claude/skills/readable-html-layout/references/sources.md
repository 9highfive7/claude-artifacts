## 1. WCAG 2.1 達成基準 1.4.8 視覚的提示（レベルAAA）

出典: https://www.w3.org/WAI/WCAG21/Understanding/visual-presentation.html

本文ブロックについて、ユーザーが以下を達成できる仕組みを求める。

| 項目 | 基準 |
|---|---|
| 1行の幅 | 80文字以下（CJKは40字以下） |
| 揃え | 両端揃え（justify）にしない |
| 行送り | 段落内で1.5倍以上 |
| 段落間 | 行送りの1.5倍以上 |
| 拡大 | 文字を200%まで拡大しても横スクロールなしで読める |
| 前景・背景色 | ユーザーが選択できる |

根拠として明記されている点:
- CJKが半分の40字なのは、同等の読みやすさで表示したとき漢字・かなが欧文の約2倍の幅を占めるという研究にもとづく。
- 長い行は読者が行を追う位置を失いやすい。低視力・認知・学習障害のある人に特に大きな障壁。
- 両端揃えは語間が不均一になり「白い川（rivers of white）」ができて語の境界が判別しにくくなる。失敗例 **F88** として分類。

達成手法（JSの位置づけに関係）:
- G204: ユーザーエージェントによるテキストの再流動を妨げない
- C20: 相対単位でカラム幅を指定する
- G146: リキッドレイアウト
- G188: 行間を切り替えるボタンの提供
- G175: 文字色・背景色を切り替える仕組みの提供

注意: AAAであり「ユーザーがそれを達成できる仕組みがあること」という書き方。制作者が固定値で守る義務ではなく、設計目標として読む。

## 2. WCAG 2.1 達成基準 1.4.3 コントラスト（最低限）（レベルAA）

出典: https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html
チェッカー: https://webaim.org/resources/contrastchecker/

| 対象 | 最低比 |
|---|---|
| 通常テキスト | 4.5:1 |
| 大きいテキスト（18pt以上、または14pt太字以上） | 3:1 |
| 非テキスト要素（UI部品・図形、1.4.11） | 3:1 |

## 3. デジタル庁デザインシステム — タイポグラフィ

出典: https://design.digital.go.jp/dads/foundations/typography/

行高（line-height）の用途別目安:

| 用途 | 行高 |
|---|---|
| 読み物の本文（最低限） | 150% |
| 読み物の本文（一般） | 160% |
| 心理的負荷の軽減を考慮 | 170〜175% |
| 見出しなど文字が大きい要素 | 140%程度（狭めたほうが可読性が保たれる） |
| 管理画面・業務システム（情報量優先） | 120〜130% |
| ボタン内の1行テキスト | 100% |

文字サイズ:
- 本文・UIは 16 CSS px 以上を基準。
- 14px は領域制約がある場合の例外。
- 14px 未満は原則として許容されない。

その他:
- 日本語フォントは通常イタリック体を持たないため `font-style: italic` は可読性を損なう。避ける。

## 4. デジタル庁デザインシステム — 余白

出典: https://design.digital.go.jp/dads/foundations/spacing/

- 基準単位として 8 CSS px がよく使われる。その倍率スケールから 3〜5段階程度を選んでスタイルガイドに定義する。
- 関連の強い要素には小さい余白、弱い要素には大きい余白を与えて文書構造を強調する。
- 具体例: 画像とキャプションの間隔を本文と同じにすると、キャプションが画像の説明か本文の一部か判断しにくくなる。
- 余白の大きい要素は重要度が高く見える。見出しレベルが下がるにつれて周囲の余白も減らすと階層が視覚的に表現できる。

## 5. デジタル庁デザインシステム — レイアウト（グリッド）

出典: https://design.digital.go.jp/dads/foundations/layout/

- グリッドはマージン・カラム・ガターで構成。12列が分割・結合のしやすさから一般的。
- **カラム幅は本文の文字サイズの整数倍**にする。
- **ガターは原則として本文文字サイズの2倍**を確保する。狭いと隣のカラムの文字と接近しすぎて誤読を招く。
- ブレークポイント例: 768px 未満／以上の1点設定。
- 記事や読み物では12カラム中の8カラムや6カラムを使うカラムオフセットでフォーカスを作る。

## 6. NN/g — ゲシュタルト近接の法則

出典: https://www.nngroup.com/articles/gestalt-proximity/

- 近接は色や形の類似といった競合する視覚的手がかりを上回るほど強い。
- 見出しは「次に続く本文」に近く、「前のセクション」から遠く配置する。
- フォームではラベルと入力欄の間隔をラベル同士の間隔より小さくする。
- 関連のない要素を近くに置くと互いを隠す。例: カリフォルニア州EDDサイトで「追加」ボタンが Next / 下書き保存 / キャンセル の中に埋もれて見つけられなくなった。ユーザーはグループ内の1項目だけを見て他の項目の中身を推測してしまう。
- チャンク化: 12個の入力欄を1塊で出すより4個×3グループに分けたほうが簡単に見える。

## 7. NN/g — F字型走査パターン

出典: https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content/

- F字は「望ましい形」ではなく失敗の兆候。ユーザーにもビジネスにも悪い。右側に置かれただけで重要な情報が読み飛ばされる。
- F字が起きる条件（3つ揃ったとき）: Web向け書式設定のない文字の壁 ／ ユーザーが効率を優先 ／ 全文を読むほどの関心がない。→ 書式を与えれば防げる。

対策:
- 最重要点を冒頭2段落に入れる
- 見出しと小見出しを本文より明らかに目立たせる
- 見出しの最初の2語に情報量の多い語を置く
- 少量の関連コンテンツを枠線や背景色で視覚的にまとめる
- 重要語を太字にする
- リンクは書式を区別し「こちら」ではなく内容を表す語を含める（読み上げ利用者にも効く）
- 箇条書き・番号を使う
- 不要な文章を削る

走査パターンの種類:
| 型 | 特徴 |
|---|---|
| F字型 | 文字の壁で発生。失敗の兆候 |
| レイヤーケーキ型 | 見出しだけを拾う。見出し設計が良いと成立。**実質これが目標形** |
| スポット型 | 特定の語を探す |
| マーキング型 | スクロール中に1点を凝視。モバイルで多い |
| バイパス型 | 同じ語で始まる行の先頭を意図的に飛ばす |
| コミットメント型 | ほぼ全文を読む |

その他: 右横書き言語ではF字は左右反転。レスポンシブでは行の折り返しが変わるため、同じページでも端末によって読まれる語が変わる。

## 8. NN/g — 視覚デザインの5原則

出典: https://www.nngroup.com/articles/principles-visual-design/

5原則: スケール、視覚的階層、バランス、コントラスト、ゲシュタルト。

- 見やすいデザインは一般にサイズの種類を3つ以下に抑える。
- 階層をつくるには書体サイズを2〜3段階使って重要度を示す。サイズ以外にも明度、色、余白、配置で作れる。
- 重要度の低いテキストのコントラストを意図的に落とす手法は危険。判読性を下げてアクセシブルでなくなる可能性があるため、必ずコントラストチェッカーで確認する。
- 歴史的言及: フォントサイズ・行高・行幅の関係に黄金比が使われ、結果として行長が短くなり余白によるバランスと読みやすさが生まれた。
- 美的usability効果: 視覚的に魅力的だと感じられたデザインは小さな使い勝手の問題を許容されやすい。

## 9. その他

### web.dev — clamp() による行長制御
出典: https://web.dev/articles/min-max-clamp?hl=ja
- `width: clamp(45ch, 50%, 75ch)` のように `ch` と `clamp()` を組み合わせて45〜75文字に収める。
- 日本語ならこの `ch` の数値は半分程度に読み替える。

### 日本語の1行文字数の実務目安（食い違いあり）
- japan-design.jp（https://japan-design.jp/design/0052/）: 1行35〜50文字、コンテンツ幅640〜900px。
- asobou.co.jp（https://blog.asobou.co.jp/web/text-design02）: 横書きで15〜35文字程度。
- 一致していない。確実なのは WCAG の上限40字。その下は媒体やフォントサイズ次第。

## 10. 情報源間の食い違いと限界

- 日本語の1行文字数は上記のとおり食い違う。WCAG 上限40字のみを確定値として扱う。
- SKILL.md の「優先順位」（行長・行間 → 余白 → 走査対策 → 階層・コントラスト → グリッド）は各出典が明示的にランク付けしたものではなく、投じる労力に対する改善幅が大きい順という整理。
- HTMLのセマンティクス、見出しレベルの入れ子構造、スクリーンリーダー向け配慮は調査範囲外。
- JSについて、レイアウトの可読性を高める用途としての推奨は一次情報に出てこない。WCAG の達成手法はユーザー側の変更を妨げない方向に寄っており、正当な用途は G188 / G175 のような切り替えコントロールの提供。
