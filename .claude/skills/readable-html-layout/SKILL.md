# 読みやすいHTMLレイアウトの法則

人が画面上のテキストを読むときの負担を減らすためのレイアウト原則と、その実装テンプレート。
ここに書かれた数値は W3C（WCAG 2.1）、デジタル庁デザインシステム、Nielsen Norman Group（NN/g）の一次情報に由来する。出典と根拠の詳細は `references/sources.md` を参照。

## いつ・どう使うか

| 状況 | やること |
|---|---|
| HTMLページを新規に作る | 下記「実装テンプレート」を起点にし、5原則のチェックリストを満たす |
| 既存ページを改善する | 「レビュー用チェックリスト」で診断 → 優先順位の高い順に直す |
| 「なぜその値なのか」を説明する | `references/sources.md` の該当項目を引く |

言語による違いに注意する。**日本語（CJK）は1行の文字数上限が欧文の半分**になる。ページの主言語を確認してから数値を選ぶこと。

## 6つの原則（優先順位順）

労力に対する改善幅が大きい順に並べている。1→4 を済ませてから 5・6 の微調整に入る。

### 1. 1行の長さと行間 —— 最初に手をつける

- **1行の幅**: 欧文80字以下、**CJKは40字以下**（WCAG 1.4.8）。実務では欧文45〜75字、日本語は媒体次第だが40字が上限。
- **行間（line-height）**: 本文は **1.5が最低限**、一般には1.6、心理的負荷を減らすなら1.7〜1.75（デジタル庁）。
- 見出しなど大きい文字は逆に **1.4程度に詰める**ほうが読みやすい。
- 管理画面など情報密度優先: 1.2〜1.3。ボタン内の1行テキスト: 1.0。
- **段落間**は行送りの1.5倍以上あける。
- **両端揃え（`text-align: justify`）は使わない**。語間が不均一になり「白い川」ができて語の境界が読みづらくなる（WCAG 失敗例 F88）。
- **文字サイズ**: 本文・UIは **16px以上**。14pxは領域制約時の例外、14px未満は原則不可。
- 日本語フォントはイタリック体を持たないため `font-style: italic` は避ける。強調は太字・色・背景で。
- 200%に拡大しても横スクロールなしで読めること（相対単位・リキッドレイアウトで実現）。

### 2. 余白で関係性を語る —— 近接の法則

ゲシュタルトの「近接」は色や形の類似より強い手がかりになる。**余白の大小がそのまま「関係の強弱」として読まれる**。

- **基準単位を8pxにし、倍率スケールから3〜5段階だけ選んで使う**（例: 8 / 16 / 24 / 40 / 64）。段階が多すぎると階層が伝わらない。
- 関連が強い要素間は小さく、弱い要素間は大きく。
  - 見出しは「次に続く本文」に近く、「前のセクション」からは遠く。
  - フォームは「ラベルと入力欄」の間隔を「ラベル同士」の間隔より小さく。
  - 画像とキャプションの間隔は本文の段落間より小さく（同じにするとキャプションが本文の一部に見える）。
- 見出しレベルが下がるにつれて周囲の余白も減らす → 階層が視覚的に表れる。
- 関係のない要素を近くに置かない。ボタン群の中に別目的のボタンを混ぜると埋もれて見つからなくなる。
- **チャンク化**: 12個の入力欄を1塊で出すより、4個×3グループのほうが簡単に見える。

### 3. 走査（スキャン）される前提で書式を与える

人はWebの文章を読まずに走査する。**F字型走査は「望ましい形」ではなく失敗の兆候**で、書式のない文字の壁があると起きる。書式を与えれば防げる。目標は、見出しだけ拾えば要旨がわかる「レイヤーケーキ型」。

- 最重要点を冒頭2段落に入れる。
- 見出し・小見出しを本文より明らかに目立たせる（サイズ・太さ・余白）。
- **見出しの最初の2語に情報量の多い語を置く**（最初の2語しか読まれなくても要旨が伝わるように）。
- 少量の関連コンテンツは枠線・背景色で視覚的にまとめる。
- 重要語は太字にする。
- リンクは書式で区別し、「こちら」ではなく内容を表す語にする（読み上げ利用者にも効く）。
- 箇条書き・番号付きリストを使う。不要な文章は削る。
- レスポンシブでは行の折り返しが変わるため、端末によって「読まれる語」が変わる。見出し先頭の情報量はそれを吸収する。

### 4. 情報の形に合わせて表現を選ぶ

同じ内容でも、情報の構造に合った器に入れないと読み手が頭の中で再構築する羽目になる。HTMLは表・SVG・コードなどを直接表現できるのだから、**文章やアスキーアートで代用しない**。代用した瞬間に理解のコストが跳ね上がる。

- **比較・対応関係・一覧は `<table>` にする**。「AはX、BはY、CはZ」と文章で並べない。列が3つ以上あるなら迷わず表。
  - 表は `<thead>` を持たせ、行の高さと罫線で走査できるようにする。数値列は右揃え。
  - 幅が溢れるときは表自体を縮めず、`overflow-x: auto` のラッパーに入れる（`.table-wrap`）。
- **図解は SVG をインラインで書く**。アスキーアートの図、Unicode文字で色や図形を近似する、罫線文字で枠を組む——これらは全部やらない。フロー・構成図・状態遷移・タイムラインは SVG で描く。
  - SVG内の文字は本文より小さくなりがち。**12px相当を下限**にし、図中に大量の説明文を詰めない（説明は図の外の本文へ）。
  - 色は `currentColor` や CSS変数を使い、本文の配色・コントラスト基準（4.5:1 / 非テキスト3:1）に揃える。色だけで意味を区別せず、ラベルや形も併用する。
  - `max-width: 100%` を効かせ、`role="img"` と `<title>` で内容を説明する。
- **コードは `<pre><code>`** に入れる。行折り返しで意味が壊れるので `overflow-x: auto` にし、本文幅（40字）の制限からは外して良い。
- **数値の傾向**は表より図が速い。ただし3〜4点しかないデータをグラフにしても得はないので、その場合は表のまま。
- 器を選んだら、その器の中も原則1〜3に従う（表のセル内も行間1.5以上、図のグループ化にも近接を効かせる）。

### 5. 視覚的階層 —— サイズは3段階まで

- **文字サイズの種類は3つ以下**に抑える。階層は書体サイズを2〜3段階使って示す。
- 階層はサイズ以外に明度・色・余白・配置でも作れる。サイズだけに頼らない。
- **重要度の低いテキストのコントラストを意図的に落とす手法は危険**。判読性が下がる。必ずコントラストチェッカーで確認する。
- **コントラスト比**（WCAG AA）: 通常テキスト **4.5:1**、大きいテキスト（18pt以上または14pt太字以上）**3:1**、UI部品・図形などの非テキスト **3:1**。

### 6. グリッド、カラム幅、ガター

- グリッドはマージン・カラム・ガターで構成。**12列**が分割・結合しやすく一般的。
- **カラム幅は本文の文字サイズの整数倍**にする。
- **ガターは本文文字サイズの2倍以上**確保する。狭いと隣のカラムの文字と接近して誤読を招く。
- 読み物では12カラム中の8または6カラムを使う「カラムオフセット」で本文にフォーカスを作る。
- ブレークポイントは768px前後の1点から始めて足りなければ増やす。

## 実装テンプレート（CSS）

日本語ページ向け。欧文の場合は `--measure` を `65ch` 程度に読み替える。

```css
:root {
  /* 余白スケール: 8pxベース、5段階だけ使う */
  --sp-1: 8px;
  --sp-2: 16px;
  --sp-3: 24px;
  --sp-4: 40px;
  --sp-5: 64px;

  /* 行長: CJKは40字上限（WCAG 1.4.8） */
  --measure: 40ch;

  /* 文字サイズ: 3段階まで */
  --fs-body: 16px;
  --fs-h2: 1.5rem;
  --fs-h1: 2rem;

  /* コントラスト: 本文4.5:1以上、補助3:1以上を満たす色 */
  --fg: #1f2328;
  --fg-muted: #57606a;
  --bg: #ffffff;
  --border: #d0d7de;
}

body {
  font-family: "Noto Sans JP", "Hiragino Sans", "Yu Gothic", sans-serif;
  font-size: var(--fs-body);      /* 本文・UIの下限16px */
  line-height: 1.7;               /* 本文は1.5が最低、1.6〜1.75が一般 */
  text-align: left;               /* justifyは失敗例F88 */
  color: var(--fg);
  background: var(--bg);
  margin: 0;
}

/* 本文ブロックの幅制限。可変幅に対応するなら clamp() */
.prose {
  max-width: clamp(20ch, 90%, var(--measure));
  margin-inline: auto;
  padding-inline: var(--sp-2);
}

/* 見出し: 大きい文字は行間を詰め、前から離し・直後に近づける */
.prose h1 { font-size: var(--fs-h1); line-height: 1.3; margin: 0 0 var(--sp-3); }
.prose h2 { font-size: var(--fs-h2); line-height: 1.4; margin: var(--sp-5) 0 var(--sp-2); }
.prose h3 { font-size: var(--fs-body); font-weight: 700; line-height: 1.5; margin: var(--sp-4) 0 var(--sp-1); }

/* 段落間は行送りの1.5倍以上 */
.prose p { margin: 0; }
.prose p + p { margin-top: var(--sp-3); }
.prose ul, .prose ol { margin: var(--sp-2) 0; padding-inline-start: 1.5em; }
.prose li + li { margin-top: var(--sp-1); }

/* 図とキャプション: 本文より強く結びつける */
.prose figure { margin: var(--sp-4) 0; }
.prose figcaption { margin-top: var(--sp-1); font-size: 0.875rem; color: var(--fg-muted); }

/* 関連コンテンツのグループ化（走査対策） */
.callout {
  border: 1px solid var(--border);
  border-left: 4px solid var(--fg-muted);
  padding: var(--sp-2) var(--sp-3);
  margin: var(--sp-3) 0;
}

/* 表: 比較・一覧は文章でなく表で（原則4） */
.prose table { border-collapse: collapse; width: 100%; font-size: 0.9375rem; }
.prose th, .prose td {
  padding: var(--sp-1) var(--sp-2);
  line-height: 1.5;                    /* セル内も1.5以上 */
  border-bottom: 1px solid var(--border);
  text-align: left;
  vertical-align: top;
}
.prose thead th { border-bottom: 2px solid var(--fg-muted); font-weight: 700; white-space: nowrap; }
.prose td.num, .prose th.num { text-align: right; font-variant-numeric: tabular-nums; }

/* 図解はインラインSVG。文字は12px相当を下限、色は本文に揃える */
.prose figure > svg { display: block; max-width: 100%; height: auto; color: var(--fg); }
.prose svg text { font-size: 12px; fill: currentColor; }

/* コード: 折り返さず自身の中でスクロール */
.prose pre {
  margin: var(--sp-3) 0;
  padding: var(--sp-2);
  background: #f6f8fa;
  border: 1px solid var(--border);
  border-radius: 6px;
  line-height: 1.6;
}
.prose code { font-family: ui-monospace, "SFMono-Regular", Consolas, monospace; font-size: 0.875em; }

/* 表・図・コードは本文の40字制限を超えて良い（幅は自身の中で処理） */
.prose .bleed { max-width: none; }

/* リンクは色だけに頼らず下線で区別 */
a { color: #0969da; text-decoration: underline; text-underline-offset: 0.15em; }

/* 強調: 日本語はイタリックを使わない */
em { font-style: normal; font-weight: 700; }

/* フォーム: ラベルと入力欄は近く、フィールド同士は離す */
.field { display: grid; gap: var(--sp-1); }
.field + .field { margin-top: var(--sp-3); }
fieldset { border: 1px solid var(--border); padding: var(--sp-3); margin: 0 0 var(--sp-4); }

/* 12カラムグリッド: ガターは本文文字サイズの2倍 */
.grid {
  display: grid;
  grid-template-columns: repeat(12, 1fr);
  gap: calc(var(--fs-body) * 2);
}
.grid > .span-8 { grid-column: 3 / span 8; }   /* カラムオフセットで本文に集中 */
@media (max-width: 767px) {
  .grid > [class^="span-"] { grid-column: 1 / -1; }
}

/* 横スクロールを起こさない: 幅広コンテンツは自身の中でスクロール */
img, svg, video { max-width: 100%; height: auto; }
.table-wrap, pre { overflow-x: auto; }

/* 管理画面・高密度UI向けの上書き */
.dense { line-height: 1.25; }
.dense button, .dense .btn { line-height: 1; }
```

## JavaScriptの使いどころ

一次情報の中に「JSでレイアウトの可読性を高める」推奨は存在しない。WCAG 1.4.8 の達成手法はむしろ「邪魔をしない」方向（ユーザーエージェントの再流動を妨げない G204、相対単位のカラム幅 C20、リキッドレイアウト G146）。

JSの正当な用途は **ユーザーが行間・文字サイズ・配色を切り替えられるコントロールの提供**（G188、G175）に限る。例:

```html
<button type="button" data-toggle="line-height">行間を広げる</button>
<script>
  document.querySelector('[data-toggle="line-height"]').addEventListener('click', () => {
    const b = document.body;
    b.style.lineHeight = b.style.lineHeight === '2' ? '' : '2';
  });
</script>
```

CSSで実現できるものをJSで固定値制御しない。特にユーザーの拡大・再流動を妨げるスクリプト（固定幅の強制、ズーム無効化）は入れない。

## レビュー用チェックリスト

既存ページを診断するときは上から順に確認する。✕が付いた項目のうち上にあるものから直す。

1. [ ] 本文の1行が40字（欧文80字）を超えていないか。`max-width` を `ch` で制限しているか。
2. [ ] 本文の `line-height` が1.5以上か。見出しは1.3〜1.4か。
3. [ ] `text-align: justify` が使われていないか。
4. [ ] 本文・UIの文字が16px以上か。14px未満がないか。
5. [ ] 余白の値が8の倍数で、使われている段階が3〜5種類に収まっているか。
6. [ ] 見出しの上余白 > 下余白 になっているか（前から離し、次に近づく）。
7. [ ] ラベル↔入力欄、画像↔キャプションが、それぞれ周囲より近いか。
8. [ ] 比較・一覧が文章の羅列になっていないか（表にすべきものが表になっているか）。
9. [ ] 図解がアスキーアート・罫線文字・Unicodeでの色近似になっていないか。SVGで描かれているか。
10. [ ] SVG内の文字が12px相当を下回っていないか。色だけで意味を区別していないか。
11. [ ] 見出しの先頭2語で内容が伝わるか。文字の壁（書式なしの長段落）がないか。
12. [ ] リンク文言が「こちら」「ここ」になっていないか。
13. [ ] 文字サイズの種類が3つ以下か。
14. [ ] 本文コントラストが4.5:1以上か（補助テキストも3:1未満に落としていないか）。
15. [ ] 200%拡大で横スクロールが出ないか。幅広要素（表・コード）は自身の中で `overflow-x: auto` になっているか。
16. [ ] 12列グリッドのガターが本文文字サイズの2倍以上か。
17. [ ] 日本語に `font-style: italic` を当てていないか。
18. [ ] JSがユーザーの再流動・拡大を妨げていないか。

## 補足

- WCAG 1.4.8 はレベルAAAで「ユーザーが達成できる仕組みがあること」という書き方。制作者の固定値義務ではなく設計目標として扱い、ユーザー側の変更（ズーム、ユーザースタイル）を妨げないことを最優先にする。
- 日本語の実務的な1行文字数は情報源で食い違う（35〜50字 / 15〜35字）。確実なのは上限40字。その下は媒体・フォントサイズで決める。
- 美的usability効果: 視覚的に整ったページは小さな使い勝手の問題を許容されやすい。整えること自体に価値がある。
- HTMLのセマンティクス（見出しレベルの入れ子、ランドマーク）、スクリーンリーダー配慮はこのスキルの調査範囲外。必要なら別途確認する。
